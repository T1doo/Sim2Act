# Sim2Act · 书生模型执行简报案例

这个案例展示真实的“选材料 → 输入目标 → 页面提交 → 书生调用读取工具 → 输出结构化简报 → 冷重开查看历史成果”。输入为合成活动交接材料，不含真实个人信息。

## 已实际验证

- 页面提交原始任务，Intern 模型读取指定材料，产生 VERIFIED 工具读取回执，并输出活动执行简报。
- 模型回答保留了活动日期、地点、设备检查条件、投影故障例外、未冻结名单及下一步截止时间。上述对应关系由本轮人工核对；没有另建自动语义验收规则。
- 关闭后端后，新 Windows 包冷重开同一运行，无须重发模型请求。
- 成果回答前置到执行步骤和原文之前。Markdown 加粗以安全文本节点渲染，原文仍可展开复制。
- 1600×900、1366×768、1280×720 都能在首屏看到回答开头，没有文档横向溢出，验收缺项仍可见；矮窗口需在成果区滚动查看全部简报。
- 最终截图无页面脚本错误；API/Worker/专用 PostgreSQL 干净退出。

## 建议视频讲解

“除了可复用的数据核对能力，我们也能把一份非结构化交接记录交给书生模型。它先读取选定材料，再整理已确认安排、执行条件、待确认事项和下一步行动。成果与来源留在同一个任务中，关闭重开后仍可查看。”

建议顺序：09 配置材料和目标 → 10 后台执行状态（仅是真实瞬间，不作为完整动画）→ 12_1600x900 展示回答。1366与1280图片用于窗口适配对比，不必都放进主视频。

## 如实保留的限制

此运行状态是 PARTIAL：工具回执已核验，完整目标语义验收 NOT_RUN，人工签收尚未提交。不要在视频中宣称“整体目标已自动验收”或“已生成可复用应用”。该案例是普通真实模型任务，不是自然语言 P-A/P-B 完整通过证明。

模型运行源码为 657418c2335ae45578ecc03d3ebf6b87c0f3fb0a；最终成果显示源码见 manifest.json 中 rendering_source_commit。新包仅重新展示同一个持久运行，没有用新显示版本冒充重新执行模型。

outputs/书生模型输出.md 是从真实返回 answer 原文提取的伴随文件；不是声称模型通过 artifact.save_text 另建了应用内制品。JSON 保留完整任务和回执。

截图来自 Windows Edge 无头渲染的真实本地界面；没有操作用户原生窗口。未包含录屏视频、安装器或模型权重，EXE 原生生命周期与完整 R0 验收仍单独进行。包内没有凭据或运行数据库。

## 复现

在启用书生模型的 Windows 应用中创建项目，导入 inputs/活动交接记录.md，按 inputs/任务目标.txt 输入目标并明确选中材料，点击开始任务。等待结束，在历史选择本次任务查看回答和来源。新执行的措辞可以不同，不应要求逐字复刻本包回答；日期、条件和未决事项需要核对原文。
