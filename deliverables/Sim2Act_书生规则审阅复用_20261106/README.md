# Sim2Act · 书生规则审阅复用

同一个规则审阅助手先处理报告提交说明，再处理另一份登记表提交说明。两次成果分别保存为 v1 和 v2。两份输入都是为录制准备的示例文本，清单来自实际书生模型调用。

| 版本 | 材料 | 实际清单 |
| --- | --- | --- |
| v1 | [原材料](原材料.txt) | 周五前交报告、经批准可延期、档案负责人待定。[成果](原材料_成果.md) · [JSON](原材料_清单.json) |
| v2 | [新材料](新材料.txt) | 周一前交表、审阅者可批准延期、保留期限待定。[成果](新材料_成果.md) · [JSON](新材料_清单.json) |

## 本机查看已保存的成果

手动打开 `.local/Sim2Act_书生规则审阅.lnk`，进入「月报与登记表审阅」项目，打开「提交规则审阅助手」，选择已有 v2 的实例 `iinstance_0c50015fda966e83b7b9d150352cef2f`。分别点 v1 和 v2 的「读取此版本清单」。这条查看路径对应现有历史记录。

## 重新执行时的操作顺序

1. 在已配置书生的 Windows 工作台准备两份材料，分别保存目标。目标是提取要求、条件、例外与待确认项，并保留逐字引用。
2. 在批准的材料与模型范围内生成应用候选。核对候选与读取、保存权限后，明确保存版本并创建实例。
3. 用原材料执行，确认 v1 已保存。关闭后台并重开后，回读 v1。
4. 为同一实例预览第二份材料的使用范围，明确确认第二次执行。完成后回读 v2 和仍保留的 v1。

实跑使用 Windows 冻结包 `21b33dc4`、真实书生模型、专用 PostgreSQL 和独立 Worker。生成、批准及执行通过产品 API 验证。原材料和新材料两次运行分别耗时约 204 秒和 250 秒，录制可用已保存结果切镜。账本记录生成 3 次请求，原材料与新材料各 1 次。两份成果均逐字核对引用、原文和制品 SHA-256。来源核验通过，语义验收未执行，人工签收待确认。三个后台周期均干净退出。[可核对的运行记录](verification.json)
