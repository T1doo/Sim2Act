## 尚缺的外部条件及其后续代码

1. **真实书生 source/controller：** `production_evidence.resolve_account` 固定 `SOURCE_MISSING`；`production_preflight` 在软件资格/Permit之前拒绝。现 Journal sender/source 限 test-only SQLite、MockTransport、空 token、live=false；普通 `worker.main` 没有该生产绑定。最小缺失是官方支持的同账户身份、独立输入/输出余额及可强制禁止新增收费/付费 fallback 的可信接口或事实结构。取得后才可实现并独审真实 resolver→生产准入/账本策略→原 sender/controller 安装；配置 token、环境变量或开发者 JSON 不能替代。
2. **真实业务/语义：** 有权使用的目标和材料、独立验收者及事前固定量表，分别评价 P-A/P-B、新/错误输入、局部修改的应变/保留集。合成 ACCEPT、结构 PASS、封存准备材料均不满足这些条件。私有留出集本轮不读取。
3. **正式发布：** 精确候选和版本的真实 owner 认可、适用范围及明确发布授权；不因此自动部署、改 main 或提高权限。内部版本现成机制不等于生产发布已实现。
4. **目标平台：** 干净 Win11 普通权限环境、明确 PostgreSQL 应用角色、原生浏览器及实际安装/启动/停止/断线/冷输入证据。Linux/JSDOM/历史 ServerCI 不能代替。远端认证已拒绝且停止，当前不安排远端 CI。

盘点发现的缺口并非全部依赖外部：集合导出、通用受控视图及更宽局部修改都是代码范围。其中首先补上可明确复用现有合同、无需新执行器或权限的 T06 当前集合 JSON 导出；后续接入[原清单 text/table 组合](ManifestViewComposition20261018.md)，其范围及执行结论单列，不改写上表基线。不为扩大功能数而新增图表模板、控制包装或重跑故障矩阵。其余较宽组件/修改能力需先冻结业务合同，不能默认为已有能力。
