# 内部 CSV 流程实例的兼容版本切换

基线 db6b5dafe5d5ccc394465a666145c93dafa4a87b；对应原 F2-T03/T04/T08 的稳定逻辑复用、内部版本与回退，及 DeliveryRemainingChecklist 的 P-B 声明式路径缺口。已有 read→sum[→report] 内部版本可在新列运行，但 lifecycle.switch_target 明确拒绝 DAG 版本切换，页面也没有入口。本轮补完整业务入口，不新增家族或模型能力。

只接受同 owner/project/app/runtime、同执行家族、同端口及冻结数值列/预算、兼容数据 schema 的内部版本。来源仍须当前完整授权及原回执复验。不混合普通实例与 DAG，不迁移、改签或删除结果。准备、查看、手动确认使用既有批准/API；历史版本切换与结果版本独立。

切换前与提交时重新核查所有实例历史、typed 结果及实际 Run 回执；有未终止的运行时拒绝切换，用户先通过已有暂停/取消入口处理。历史读回可使用经已消费切换批准核实的原 revision/release；执行、继续与最终提交仍必须匹配实例当前 revision/release，不能用历史读取放宽 worker 门。

页面手动选择目标、准备、核对精确批准并确认，未确认不切换。接受结果不确定时不自动重发；通过只读恢复实例核对实际 revision/历史。导航、身份/项目/实例切换不得使用迟到批准或回执。冷页与历史只 GET；后续新输入使用当前版本重新运行。

验证使用合成 SQLite、TestClient/实际 worker 和零模型对象，覆盖两/三步升级与回退、保留旧成果、不同新列、冷历史、active-run/ABA/撤权/跨 scope/结果篡改拒绝和页面行为。PG、Windows、原生浏览器与真实模型验收 NOT_RUN；已知 Chromium 沙箱拒绝不重试、不绕过。整体 P-A/P-B、semantic/owner、正式发布和 Windows 容量门不提升。

## 使用

1. 在原应用的有限节点组合中分别成功运行两份相同结构的读取→求和（→报告）计划，各自手动保存为内部版本；仍须相同应用、列范围和预算。
2. “读取已有版本与实例”，选择实例并“只读恢复实例与结果”。下方“升级或回退此实例的内部版本”会列出兼容目标。
3. 选择目标，点击“核查目标版本与保留结果”。核对旧版本、目标、实例修订和保留条数，勾选确认，再点击“确认升级或回退”。准备不会切换版本。
4. 旧结果保留在各自原版本下。选择新的数值列，另行确认并排队，实际 worker 会执行新流程并追加结果。回退也执行同样的精确核查和确认。
5. 有排队/运行/暂停等未终止任务时，先在现有入口完成或取消它。回执不确定时点击“恢复原请求回执”，本次切换恢复只读取持久历史，不重发提交。结果尚不确定时保持阻塞，勿重新提交。

本轮针对当前源码产生的新内部版本；既有跨源码图基线失效策略不变，不改签旧数据库或承诺任意旧来源自动升级。
