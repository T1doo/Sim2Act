# 固定合成目标的整体验收（离线）

按 [临时离线入口](NaturalActivationQuickstart.md)启动普通页面。默认不启用整体验收；旧任务保持原 PARTIAL，不能补签或直接改成成功。

1. 选择已有 OFFLINE_TEST 范围、打开固定 CSV 预览或 quantity_z 求和目标。
2. **在生成新任务前**勾选“为本次新任务冻结固定合成目标整体验收”。生成后选择被冻结；丢失接受回执只能恢复原接口、原来源版本和键，不会退回旧规划接口或改验收模式。
3. 阅读计划和固定契约 `fixed-csv-goal-acceptance.v1`，再单独确认只读执行。确认前没有工具效果，也没有整体验收 PASS。
4. 执行后查看“单步 VERIFIED”与“限定整体 PASS”。只对这个明确合成目标、冻结资源和版本有效：预览必须返回完整绑定 CSV，求和必须独立精确核查 quantity_z19；来源变化、缺失/未知回执、取消或部分失败不得给出整体成功。
5. 成功求和任务可按 [现有候选指南](NaturalReceiptCandidateQuickstart.md)绑定已有授权新 CSV，保存候选并验证 quantity15、新持久结果版本、错误输入及冷读取。此时来源显示 SUCCEEDED/固定契约 PASS；候选适用范围仍须人工核对、owner PENDING、未发布、完整 P-B 未验收。预览目标虽然可以有限验收成功，暂不支持生成 CSV 求和候选。

不勾选时继续旧单项回执候选路径，来源 PARTIAL/整体 NOT_RUN，不晋升成功。已固定模式的请求键不能用于另一模式。所谓“固定整体 PASS”不是自由自然语言语义正确、模型自主归纳、用户签收或正式发布。内部工程验证与正式发布门不变。

这里只是手写离线适配器与真实注册工具。没有真实 provider 请求、费用或授权扩张；无新表、API 建表或默认 LIVE 开通。HTTP/JSDOM 不替代 Win11/真实浏览器像素或 PG 角色验收；Windows900/Edge240/Node150 原标准不变。临时入口退出后自己的数据全部删除，不能把退出后的测试库当生产冷恢复证据。
