# Saved goal → durable task: bounded product slice

Base eb79cb5. Original V5 P-A requires model-selected ActionSpec/AppManifest; P-B requires an actually completed task and verified source. Existing CSV templates and test-only Report protocol do not satisfy these. Report LIVE additionally needs a separately approved global budget policy; this slice neither enables it nor claims that only LIVE validation remains.

User deliverable: open a saved GoalCard, explicitly run its saved version through the existing ordinary durable Run/worker, and inspect this new Run's actual tool receipts/result/history. No retyping the goal or silently losing known facts, assumptions, unresolved questions, hard conditions or acceptance checks. No automatic application candidate, Principal/Grant, publication, model request, schema or migration changes. Tests use Mock only as offline contract evidence.

Closed POST /api/projects/{pid}/goal-cards/{cid}/runs accepts only expected_version, expected_fingerprint and request_key. Server project/goal/history/current-resource checks and enqueue share Store.submit's transaction. FrozenRunContract gets an optional typed source binding; legacy contracts remain readable and ordinary new contracts omit absent sources. Idempotency binds card/version/fingerprint and execution policy; lost acceptance recovery returns the same Run after a later text revision, with original frozen conditions. Changed resource/permission or a different original input is rejected.

The normal worker validates the source before execution and each request reservation, feeds all frozen GoalCard fields into the first actual request and keeps them on resume. Tool gateway, budget, returned-model policy, Attempt/Operation, fencing and receipt checks remain unchanged. Final ordinary result stays PARTIAL with goal_acceptance NOT_RUN; it cannot become P-B SUCCEEDED provenance. No LIVE/models calls, automatic retries, budget increases or protocol guard removals.

Required offline contracts: actual HTTP/default worker full-input and receipt path; legacy ordinary run; same-key and lost receipt; changed version/fingerprint; cross-owner/project; history/source/permission tampering before send; later goal edit preserves accepted source. UI: immutable submitted body/key, explicit unknown recovery, selected project/identity/card generation and ABA protection, read failure uses existing Run instead of reexecution. Use controlled DOM with real product assets and actual loopback HTTP where available, label native pixels NOT_RUN.

Independent review, focused related tests/static checks and evidence follow implementation. Do not repeat whole SQLite/PG or Windows CI. Original full7854 and R0 evidence stay bound to their actual source. Normal development push uses [skip ci] while native900/Edge240/Node150 remains NO_GO. Separate native phase ledger and coverage-preserving optimization proposal must distinguish measured Windows values from Linux estimates.
