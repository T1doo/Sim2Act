# 自然应用首次创建连续向导

基线：`9d12e321d556c4b9c6ec2bf1ef4ccd7b958a645c`。从应用目录的“从 Goal 创建自然应用”开始，无需已有应用、Release 或实例。

1. 复用应用内 TXT/MD 准备及保存表单，保留非空白 UTF-8 / 2048 字节 / 40 行与 Unicode C 限制。材料保存和只绑定该材料的新 Goal 保存分别明确点击；未保存编辑不生成任务。
2. 明确继续后恢复原 Goal 表单与自然候选生成面板，绑定刚保存的 Goal 版本。默认应用名最多 100 Unicode 码点，完整 Goal 标题和正文保持。
3. 点击原生成按钮时先以 GET 读取当前配置，捕获连接、项目、Goal 版本/指纹及页面/编辑代际。没有可用配置则明确停止，不建立生成意图、不 POST application-runs。合法离线配置下仍须此次明确点击生成；不自动提交。
4. 原模型候选回读控制器核对原请求、完整目标、样本与指纹。原材料读取确认与项目 JSON 保存授权仍分别勾选，另行点击确认候选。未确认时不创建应用。
5. 使用原内部版本控制器核查精确快照，单独确认保存 Release，再明确点击该版本的“创建独立实例”。版本和实例保存不执行实例。
6. 精确实例回读后，向导显示“返回应用目录，使用此应用”。返回仅重新读取目录，不运行实例。目录中的应用可继续使用第二份材料及其 Goal，按原 per-use 预览和确认流程提交新 Run。

向导步骤卡在受控页面跳转之间保留。用户切换账号、项目、页面、Goal 或另选应用会结束原向导；旧能力 GET 不会迟到提交，原候选/版本控制器的异步回读仍受原守卫约束。取消不会删除已保存内容、取消后台任务或重发。原请求与未知回执策略保持；Goal 新建仅页面内存防重复，不声称跨冷页幂等。

自然家族现有 API 明确拒绝 activation，尚无 LIVE 批准路径。新增 `/api/capabilities.natural_spec_generation` 是只读可用性 metadata，不能授权发送：仅 `Store.test_only`、`mode=mock`、`live_enabled=false`、`goal_planner_provider=intern-s2` 表示 `OFFLINE_TEST_ONLY`；其他配置为 `BLOCKED`，真实请求额度始终 0。即使 metadata 可用，实际发送仍由未修改的 `check_provider` 要求 `httpx.MockTransport`。不复用其他家族 LIVE 批准，不创建新批准、executor 或 Grant 种类。

原 `openGoalApplication` 完成整段候选打开读取后，才解除只用于打开阶段的 `engineering.selectionCurrent` 守卫，然后切换到 Apps；后续动作使用原内部控制器自己的代际守卫。这避免原页面跳转使刚打开的内部按钮永久失效。没有提前放松异步打开守卫。

本轮仅有界 mock 验证：空目录新材料 / Goal → 候选 / 内部版本 / 实例 → 目录 → 第二材料首次实例结果，以及缺配置、页面隔离和受影响共享表单 / 目录回归。不追加旧 P-A/P-B 恢复矩阵，不处理旧多历史心跳锁问题，不代表真实语义或真实场景通过。
