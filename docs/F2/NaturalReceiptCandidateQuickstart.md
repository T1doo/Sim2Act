# 单项可信求和回执 → 未验收候选

本入口复用现有 CSV ActionSpec/AppManifest 与运行器，限已批准 OFFLINE_TEST 合成求和回执。来源 Run 仍为 PARTIAL；“候选保存”不会把整体目标改为成功，也不会发布应用。固定 CSV 预览目标暂不支持这一提取。

1. 按 [离线体验指南](NaturalActivationQuickstart.md)启动临时入口，选择已有 OFFLINE_TEST 范围、固定 `quantity_z` 求和目标，生成计划并逐计划确认，取得真实工具回执 19。这里仍使用固定手写离线适配器。
2. 在同一项目的材料工作区保存不同的新 CSV，例如：

   ```csv
   amount,quantity,bad
   30,6,x
   50,9,y
   ```

   在“应用”建立绑定该材料的初始 CSV 草案作为已有授权目标。新回执候选沿用这个应用的共享授权域；生成不会另增身份或授权。
3. 从任务历史重新打开原求和 Run。在“单项可信回执”区域核对来源 PARTIAL / 整体 NOT_RUN、创建时新 CSV 绑定、运行时 column 变量、固定 aggregate_csv@1 只读逻辑，选择目标和名称，点“保存单项回执候选（未验收）”。没有合法目标时先补既有授权目标，不绕过权限。
4. 打开保存候选，选择 `quantity` 作新预览，实际结果应为 15，而不是复制源结果 19。新结果来自新材料；候选来源与整体未验收标识保持可见。非数值列 `bad` 应是当前 FAILED，不能显示旧成功作为本次成果。
5. 如需验证持久结果版本，按 [已有内部 CSV 验证步骤](RegisteredRunQuickstart.md)核查并人工确认内部工程快照、创建实例并提交新 AppRun。每次新任务显式选 quantity；这是内部验证流程，正式发布仍关闭。

生成接受结果 UNKNOWN 时，仅显式恢复冻结的原来源/目标指纹和请求键；没有自动重发。回执必须与服务端保存候选完整来源绑定吻合，错 ID 或错类型回执不会丢失恢复入口。冷页读取候选/历史不产生新任务；来源材料/回执/批准范围失效或来源/目标撤权后，读取、缓存恢复及运行仍拒绝。

临时服务退出会删除自己的全部合成记录，退出后不能恢复该测试库。HTTP/JSDOM 测试不等于真实浏览器像素或 Windows 原生验收；PowerShell 示例尚未原生验收。此有限检查不证明模型自主变量归纳、一般自然语言正确、整体完成任务源、完整 P-B 或正式发布。
