# 下一非 CSV 真实任务候选：技术规格 → 带来源的检查清单

2026-10-06，仅建议/离线合同，不实现新feature、不调用模型。依据原V5产品§1.3“资料整理与带来源内容生成”、F02/F05/F06/F08、P-A/P-B及§12“引用定位不等于语义正确”。这是一个有既有真实材料的任务族候选，不是新行业栏目、网站或通用应用完成声明。

**目标**：从有权使用的技术规格MD中整理明确的上线/升级约束，输出带材料版本、hash、原行号和原文证据的JSON清单，受控MD报告由同一已校验JSON确定性渲染；最小源任务仅保存JSON成果，MD为派生视图，不额外生成或宣称第二保存回执。价值是复用原始约束、检查遗漏，并在文档版本改变后保守重验，避免靠记忆复述规格；不声称已测用户省时或业务收益。

最小真实来源为仓库内原用户V5《平台产品设计》§10.1（450—458行，选段UTF8 822字节）；本地读取已获授权，**发送这些真实文档到Intern仍需单独明确同意**，本轮AT02合成TXT42/84明确授权已执行并用尽，不能扩用于后续真实Markdown材料。固定4段：Release/instance/preview隔离；version CAS/Run固定版本/每动作动态权限；兼容升级/破坏迁移拒绝/回退兼容；版本回退不等于数据回退/动作撤销。完整文件hash+选段范围+版本1冻结，输入只能项目逻辑资源ref，不接受路径/URL/凭据目录；后续同族范围MD/TXT UTF8<=4096bytes、<=40行、明确规范段落，无扫描/OCR、外网检索或跨项目资料。不自动把未知期限/权限/规则解释成允许。

**独立oracle**：预先由材料owner/验收者冻结每个规范段的必需约束与禁止推断、引用和人工语义量表。当前4段由开发方按源文预置的gold草案见[离线合同](../evidence/AT02-budget-preparation-20261006/noncsv-contract-results.json)：结构/源hash/版本/四项无缺漏、原行号与完整quote一致；wrong hash/stale version/missing rule/wrong quote/wrong span五负例均拒绝。该草案尚待材料owner/独立验收者确认；这里只校验gold的合同，不是模型实际提取；引用存在仅证明出处，模型paraphrase的含义/遗漏/多余承诺另按固定人工gold核对，不能以引用匹配代替语义评价。未见输入必须另外冻结gold，不能沿用这四段答案。

P-A方向：owner给目标+新版本材料和验收契约，真实Intern选择受限读取/来源定位/结构化结果方案，形成可信声明式候选；不要求用户手写JSON才算生成。P-B方向：先完成真实清单任务并保存输入hash、实际工具/成果及独立oracle，通过可信终态/回执形成来源证明，再提取材料ref/版本、选段范围、规则类别、格式等可变参数，消除原会话/绝对路径，使用未见版本/缺字段/错误hash/撤权/冷会话验证。不能直接拿旧F1 PARTIAL Run冒充成功P-B来源，不能只换标题或重放旧清单。正式发布仍另门，不自动启动。

**必要依赖与最小门槛**：现F1已有resource.read与artifact.save_text可做MD/JSON文本成果，但F2候选/完成task proof仍封闭在CSV固定工具族；需另阶段明确可信“来源定位/清单结构检查”ActionSpec与受限模型判断、MD/JSON成果回读oracle/依赖版本，然后扩同一个声明式运行器，不能任意代码/插件/自由SQL兜底。通用业务writer不作为此任务依赖；这里只生成本地报告，需显式最小artifact写授权和真实receipt回读/命名空间，不能顺便开正式发布。
