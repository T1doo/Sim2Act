## 实现前隔离合同

1. 用户先选择原应用的精确内部 Release，单独确认“创建私有试写空间”。服务端派生 owner/project/App/runtime/Release/候选/软件指纹，保留独立创建回执；客户端不能指定存储 namespace、真实目标实例、路径或工具。私有空间仍是原内部实例和原 durable Run 的有界用途，不新增 executor、Principal、Grant、表或系统权限。
2. 私有空间由独立不可变创建锚识别，业务实例清单不混入它；目录在独立分组中明确标为“私有试写”。原记录命令、预览确认、Run/AppRun、Worker、租约/fence、Operation/Intent/Receipt、typed/CAS 与状态折叠复用。CREATE 和 OPEN→DONE 的类型、容量、版本和禁止副作用不放宽。
3. 原 `artifact.save_text@1` 增加服务端受信的私有目标上下文，普通调用路径保持原资源写入与派生授权行为。私有目标必须在每次写入/回读时，从实际创建锚、Run/Operation 和当前权限重新核对；仅 context 标记或客户端字段不能获得该目标。
4. 私有 JSON 内容及真实保存回执落在原 `app_previews` 私有存储；不插入 `resources` 或 `grants`，不出现在普通材料目录，不改变项目 Grant 指纹、业务依赖/审批基线或真实实例。私有内容有真实对象ID、hash和事务回读；不是只计算后回滚，也不是内存样例。原普通资源 API 不解析私有对象ID；没有私有到业务资源的隐式回退或查找。
5. 私有保存、Operation/Receipt、typed 追加与该私有实例 CAS 同事务；失败整体回滚。所有既有业务行、资源及 Grant 字节保持。允许新增的原账本行必须逐一绑定私有实例/Run/Operation及PREVIEW作用域，不因在同一物理表就排除整张表检查。
6. 私有读取使用当前 owner/project 和原 `artifact.save_text` 权限交集核查，不新发 READ Grant。先核标量作用域与权限，再读内容；另一账号/项目/私有空间或业务实例不能读取或引入该内容。撤回后仍沿原元数据控制入口停止原 Run；历史留存不代表当前可读。
7. 试写结果不是业务成功来源、正式发布证据或人工签收，不可被现 P-B/业务资源接口降级消费。没有晋升/复制/采纳接口；要保存业务数据，须明确选择业务实例、重新填写并确认新的原业务 Run。切换私有/业务空间清输入和未提交确认，不自动迁移记录。
8. 页面沿原身份/连接/项目/工作区/App/实例选择代次和持久意图控制器。双击不重复；未知提交仅原键 GET，任何迟到回读不能填入另一空间。冷重开可明确选择同一私有空间，回读同 Run/真实存储成果。
