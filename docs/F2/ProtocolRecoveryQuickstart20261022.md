# 协议任务恢复与完成回执：操作说明和交付边界

更新于 2026-10-22；核对开发分支 `dev/production-trial-stages-20261018` 的 `4f3454d27464f9775223a5b416a0c88a74e56af7`。本说明收口 F2-T09 / AT-05、AT-18 的有限已交付子项，不代表完整验收。当前 V2 完成及其完成回执定位入口仅支持已有 `test_only` / `mock` 合成库及其持久证据，不因此开放普通生产库、真实账户或模型。安装、令牌和后台启动仍按[安装说明](../Installation.md)；不要为恢复任务重新初始化用户或创建新运行。

## 已完成任务：刷新后只读找回

1. 重开页面或硬刷新后，用原身份重新连接，选择原项目，在任务列表找到**原 Run**，点击该行的 **“查看任务”**；在“注册任务与可复用协议成果”下的“当前协议成果”核对完整 Run ID 和阶段。未找到时先核对身份/项目/当前读权，不新建任务来代替原任务。
2. Source 或单请求 Extract 已通过 V2 完成命令结算时，点击 **“找回已完成任务回执（只读）”**。页面只发认证 GET，定位原完成键和持久回执，再新鲜读取当前成果；不创建新键、不补传响应，也不执行完成 POST。
3. 核对显示的原请求键、版本/fence 和成果指纹。原 Source 完成回执的技术状态仍是 `WAITING_APPROVAL / UNKNOWN`；若后来已有有效的独立 `review_proof`，当前详情可为 `SUCCEEDED / PASS / APPROVED`，不需要因此重复核查。没有该证明时须另行独立核查。Extract 的已编译草案是 `SUCCEEDED / NOT_RUN`，不等于 Cold 执行成功。两者 owner 仍 `PENDING`，尚未发布。
4. 查无记录、无权、格式冲突或成果复读失败时，页面显示 **“当前完成状态不可确认”** 并关闭当前成果与提取/Cold入口。旧键/回执可保留为历史，不能当作今天已确认。`NOT_FOUND` 只表示未找到可认证的 V2 完成命令；普通 Worker 已完成但没有该命令也可能如此，不能据此认定未执行或换键重发。
5. 需要重新核对时，明确点击找回按钮，或点击 **“重新读取成果与核查状态”**。后者按原业务规则复读当前成果，不制造 V2 完成键。当前授权/来源/版本必须仍有效；自动轮询不会自行清除读取失败投影。不要通过刷新、新键、重复运行或修改数据文件绕过拒绝。

回执找回只读取已持久的完成事实。未被持久记录的未知命令不会因页面重开恢复。当前读权/撤权/来源封印每次重验；历史执行期限已经过去不自动抹掉当时合法完成的回执，也不表示现在还能再次执行。今天已无读取权限时，历史成功不授予访问权。

## 尚未结算：保留原命令，不重发模型请求

只有当前 Source 已收妥完整响应和工具回执（V2 READY），或普通单请求 Extract 已持久接受候选（V2 ACCEPTED），才可能使用“已知响应的任务结算”。勾选只结算当前已接受任务，再点 **“尝试完成当前任务”**。服务端仍检查原期限、租约、版本/fence、授权和全部账本；按钮可见不保证可完成。它不接收用户上传响应、usage 或补证，不再发送模型请求、不重新占额或接受候选。

双击沿同一页内命令处理。完成响应丢失/损坏时保留 `UNKNOWN` 和冻结原键/参数，只能显式点 **“用原完成键核对回执”**，以原完成 POST 的相同键/参数做幂等核对，不是只读 GET；不能把错误或超时解释成未执行。已确认完成而成果 GET 失败时只重新 GET，不再 POST。切换任务或关闭工作区后迟到响应不能覆盖当前选择。整页刷新会丢失未持久的页内命令；若服务端尚无可认证完成回执，保持不可确认，不生成新键代替它。模型发送/结果证据为 STARTED/UNKNOWN、旧 V1、缺 usage、未决 Operation、Cold完成或不支持的提取形态继续拒绝；这里的证据未知与上文完成命令回包丢失的传输 UNKNOWN 不同。

## 三种回执入口各做什么

| 页面操作 | 用途 | 不会自动做什么 |
| --- | --- | --- |
| 找回已完成任务回执（只读） | Source / 单请求 Extract 原 V2 完成命令的原键和回执，再复读成果 | 不结算、不核查、不新建请求 |
| 找回已接受核查回执（只读） | Source / Cold 已接受的独立注册合成核查事实 | 不把完成回执或查无记录当核查 PASS |
| 核对持久状态（不继续执行） | 原状态/账本核对命令，可留元数据回执 | 不继续运行、不补证、不重新发模型请求 |

表中前两项是只读 GET；“核对持久状态”使用原状态核对 POST，不是继续执行，也不属于本次零 POST 的只读窗口操作。

Source / Cold 的 **“请求已注册合成核查”** 是另一项显式业务命令：必须另行勾选确认，固定接受时的合成契约，不接受自填 PASS。核查回执本身不能解锁；须新鲜读取匹配的当前成果和独立核查证明。注册核查不是 owner 对真实任务签收，也不自动提取、Cold或发布。Source 完成后确认框在本次实际浏览器复读时没有立即可用；原 2500ms 轮询使其约 1124ms 后恢复，本次真实勾选/取消通过，未点击核查提交。
