# Explicit registered synthetic review request

The original `ProtocolStoreLoopPlan.md` allows the owner to request an independently registered evaluation, without supplying PASS, gold or a checker. `ProtocolUiEntryLog.md` recorded that this backend action had no UI entry. A Source could therefore be technically completed into WAITING_APPROVAL while its existing extraction button remained unavailable.

The selected Source/Cold result now offers a separate, unchecked confirmation to request the existing fixed synthetic checker. The verified Run response exposes only its enqueue-time `contract_id`. The request binds that ID, original result fingerprint, version and fence, plus a new page-generated request key. It does not read the currently selected source/cold form contract, submit a verdict, register an evaluator, grant access, or start extraction/Cold automatically. Only the four existing `protocol.synthetic.{a,b}-{source,cold}.v1` contracts are eligible.

Double clicks share one pending command. A lost or invalid response remains transport UNKNOWN and can only be explicitly retried with its original body/key. A known PASS, FAIL or business UNKNOWN receipt permits only GET recovery. PASS never unlocks from the receipt alone: the original authenticated Run inspection must return its matching contract, result fingerprint, fence, version+1, SUCCEEDED/PASS/APPROVED. FAIL/business UNKNOWN keep the original version and WAITING_APPROVAL/UNKNOWN. Owner acceptance stays PENDING and publication stays disabled. The existing backend keeps its current authorization/provenance checks; completed-result review does not acquire a new worker lease.

Commands stay in page memory under identity/project/Run. Workspace close/return and selection changes clear confirmation and prevent late responses from repainting the view. A per-command read generation prevents an older failed GET from replacing a newer confirmed read. A pre-review Run render cannot confirm a later FAIL/UNKNOWN receipt. Refreshing or closing the page loses these keys; users must first read the persisted task state. No cross-page recovery is claimed.

Validation is in `docs/evidence/protocol-review-ui-20261022/README.md`. It includes a real Source HTTP/SQLite round trip over sealed accepted facts and controller VM checks for both phases. The new controls have not received native browser/pixel validation; the earlier Source completion Edge result applies only to its frozen historical checkout. Cold HTTP, real providers, PostgreSQL, G0 and overall F2/R0 are outside this result.
