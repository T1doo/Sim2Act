# 从成功 CSV 任务保存可复用草案

前提：使用仓库已有本机 MOCK 安装，API、worker 和数据库已启动；浏览器连接已有本机身份。启动步骤见 [README](../../README.md#windows-原生复现说明待实测)。保持 MOCK，不需要模型密钥、LIVE 或新部署。既有安装按原显式 migrate/应用角色 CRUD 说明升级；本入口没有新表，不让 API 建表。

1. 在同一项目准备两份不同 CSV，并在“应用”分别建立已有授权的 CSV 草案。例如源 `amount` 列为1、2；新材料有 `amount,quantity`，两行为 `10,7`、`20,8`。这是明确的材料授权前置，保存可复用草案不会自动补权限。
2. 打开源草案，选择 `amount`；点“核查并准备内部快照”，展开核对后勾选确认并保存内部 Release，点“创建独立实例”，提交新持久 AppRun。worker 处理后点“重新读取内部历史”，打开成功 Run；例子源结果为3。
3. 点“将这次任务保存为可复用草案”，检查来源证明，选择绑定新 CSV 的已有应用及草案名称，然后保存。这里沿用所选应用的共享授权域；撤回它的授权会同时影响新草案。
4. 新草案打开后选择 `quantity`，按同样步骤核对并确认内部版本、创建实例。**提交每个新持久任务前，再在下方“冻结材料的数值列”选择 `quantity`**，然后提交并回读历史。例子新结果为15，使用新的材料、Run和结果版本，源答案3不作为新结果。

预览选择与下方新任务参数分别设置。刷新历史后，新任务表单可能默认回到首列 `amount`；本例提交该列会得到30。已有历史中的 `quantity=15` 不随表单选择改变。

关闭页面不取消已接受任务。若生成回执丢失，使用页面“用原请求键恢复生成回执”；不自动重发。若草案已创建但回读失败，用草案回读恢复按钮，不再次创建。刷新后重新连接并从草案/内部历史回读。

没有可选目标时，先核对同项目是否已有授权的、绑定不同内容 CSV 的初始应用；不要把撤权后的旧记录当授权。权限撤回、来源/版本冲突或失败来源会拒绝继续，保留历史。这里只支持可信 CSV 求和的内部工程入口，目标语义未验收，正式发布关闭；不代表完整 P-B 或模型自主生成。
