## 两种形态：同一受限机制，语言决定不能预填

下列输入仅拟用新合成TXT/MD，无真实V5/用户业务内容；具体原文字节、hash和允许外发清单先离线冻结，再一并确认。只是实验设计，尚未创建产品任务家族。

| 形态 | 用户任务/源材料 | 真正未见输入与失败样例 | 独立验收 |
| --- | --- | --- | --- |
| A 单文档义务提取 | 短合成维护通知：将自然语言条件、义务、例外、未知项整理为带原句证据清单；如只有值班确认且日志完整才可升级，临时账号不得自动沿用 | 新通知换措辞、顺序、例外和缺失条件；不得只替换数字。含无关文本/指令注入/无根据期限，必须忽略或标未知 | 先冻结逐项必要义务、禁止推断、引用span及owner人工量表；检查条件与例外未丢失，无多余承诺 |
| B 多材料冲突判断 | 两份短合成请求与规则：判断每项请求有明确支持、冲突或材料不足，输出两侧证据和缺失信息；不实际批准或执行业务动作 | 新请求与新规则同换，含否定/例外/互相矛盾/缺证据；新材料数量和角色仍在冻结上界 | 先冻结各项判定、两侧来源和可接受解释；无明确优先规则时必须保留冲突/未知，不能自行决定谁权威 |

建议每形态源包与冷输入包各<=1024 UTF8字节、<=24行，B最多2个资源；这只是待冻结上界，不是发送授权。旧合成42/84可继续作为离线权限/主体隔离对照；重复真实echo最多验证接入，不足以证明语言理解、任务应用化或两种形态。原42/84许可不自动覆盖新合成文本，也不覆盖V5真实段落或新artifact写权限。

## 谁决定生成和规划，谁验证

- 用户/独立验收者决定目标、输入范围、允许工具/预算、冻结语义验收；确认材料和共享授权域。用户不写候选JSON，不先给完整工作流。
- 产品书生Intern决定实际读取/参数映射、来源支持的语言结果；在P-B单独读取**已验证的显式轨迹/成果/检查摘要**，提出可变字段、稳定操作、保留的语言判断、输出结构、适用限制。开发用Codex不作为产品模型，也不把预填gold交给书生。
- 服务端只做严格schema/可信目录/接线编译、权限交集、范围和版本/hash/预算检查。可给两种形态共同的受限组件和输出schema，但不能根据任务类别硬编码步骤、结论、义务或规则优先级；不执行模型代码/自由SQL。
- 独立机器检查来源hash/版本、逐字quote/span、结构、记录完整性和当前权限；这些只证明出处和工程约束。独立owner/审阅者按发送前冻结的gold和量表判条件、例外、矛盾、遗漏/幻觉；模型不得自行给自己成功，也不能以“quote存在”替代语义正确。
- 源材料和模型生成器均不可见隐藏测试答案；新包的gold留在独立验收侧。开发gold须独立确认，否则语义仍NOT_RUN。一次源成功最多支持受限候选，不能声称一般化。

## 一次性预算提案（待批准，不立即询问或执行）

建议两种形态各跑一条有界P-B链，**全局最多14次真实请求**，不用完不补测：每形态源任务最多3次、从已验源提取候选最多1次、未见材料冷新Run最多3次，共7；两形态分开计分。源任务或验收失败则该形态不做提取/复用，其剩余slot不挪作重试；无效候选、缺权限、输入过大、用量未知、HTTP错误/截断或任何预算门触发即停相关链。无自动retry、repair=0、无models探测、无额外连接/文本试请求、无P-A分支。

| 约束 | 统一拟申请上限及依据 |
| --- | --- |
| 内容/身份 | 固定intern-s2与当前身份策略/官方transport；只允许冻结新合成源/冷包、目标、schema、当前权限下真实公开工具反馈及脱敏来源摘要；不送gold、token、真实文档、其他项目记录 |
| 每次输出 | <=1024 tokens，维持现平台cap；结构化候选先离线验证尺寸，截断即失败 |
| 每次完整发送体 | <=8000字符且<=10000 UTF8字节，必要schema/回执不删；相对旧2000字符许可为明确待批变化 |
| 请求/时间 | 14个全局持久slot，每源/新Run<=3、生成<=1；间隔>=6秒，max_tools<=4、max_repairs=0、每Run<=300秒，维持平台硬cap |
| 总量 | 全实验实际已知tokens与保守reservation各<=64000，单源/新Runreservation<=24000、单生成<=8000；二者或14slot先到就停。未知用量不记0、不返还slot并停发；上界不承诺14次均可完成 |
| 权限 | 仅当前显式获授权合成资源read；不新增Principal/Grant、artifact写、业务写、外部发布、部署。若不存在足够read交集，报阻塞不补权限 |

14只是明确可审的请求上限，**当前可用仍0**。完整wire上界尚未针对这两个未冻结包实测；旧非CSV计划的2530/3613/6184字符仅说明2000可能不足，不能移作本实验预检结果。离线真实序列化三阶段并验证所有保守envelope后，若不适配本提案必须先统一修订提案，不能执行中逐次索要请求或提高cap。不承诺费用，沿用usage已知/未知分类。旧2次待批及真实V5源任务3次提案均不叠加成16/17/19次。
