# 第一次使用：从 CSV 到自己的运行与历史

当前可体验的是固定 CSV 求和、私有草案、内部版本和本地运行；不是模型自主制作、正式发布或完整 P-B。本指南实际体验证据基线仍为 `de907327dd5b3105c169008a9fe0c90dcc353a8b`；后续冻结 `7854029` 的完整 SQLite/PG 回归已自然通过，并完成逐用例、来源和清理审计。当前原生预算门仍为 NO_GO，[P-B 状态](F2/PBBoundedDeliveryStatus.md) 仍为 NOT_ACCEPTED；旧指南失败记录按原样保留。

本说明的页面步骤已在 Linux 的干净合成 SQLite 测试库、真实 HTTP/product JS 和正常 Worker 上执行；仅预建测试 schema 和固定合成登录身份，不预置项目、候选、Release、Run 或结果。普通用户 PostgreSQL/PowerShell 安装、真实浏览器像素、Win11 首次体验 **未测**，不能据此签收。实际证据与失败见 [核查记录](evidence/first-use-bounded-20261007/README.md)。

## 先让后台能运行

按 [安装说明](Installation.md) 完成依赖、私有 `.env`、显式迁移及应用角色 CRUD、Doctor、本机身份和 Start。浏览器打开 Start 输出的 `127.0.0.1` 地址，输入已有本机令牌连接。保持 MOCK、LIVE=false；不要添加模型密钥、使用管理员数据库角色或放宽安全设置。预检 PASS 只是依赖/配置存在性通过，不证明数据库可连接或 worker 正在运行。

需要 **API 和 worker 都正常**；单独打开网页只足以保存草案和请求。Windows 用已有 `Status.ps1 -Config .env` 核对，不用手工造 Run/结果或反复提交解决等待。应用角色建表不足/权限错误交管理员按显式迁移处理，不由页面或此演示代办。

## 保存自己的合成材料和私有草案

1. 在“项目”输入名称，点“创建项目”。成功后会选中服务端返回的新项目，并执行原有项目切换清理；等待期间若手动切换项目或账号，则保留最新选择。保存材料前，核对页顶“当前所选项目”和原选择器均为预期项目。
2. 切换“资源”，选择自己的单个 `.csv` 文件：无 BOM 的 UTF-8、1–32768字节。选择只在浏览器中读取，核对名称、字节数、目标项目和下方内容后再保存；不是自动上传或授权。原文件换行会保留，手工改字段后转为文本模式。也可名称填 `first-use.csv`、类型选 `csv`，直接粘贴以下合成文本：

```csv
item,amount,quantity
A,10,7
B,20,8
```

3. 点“保存并授权项目内使用（24小时）”，等待材料出现。保存回执未知时禁止重发，点“刷新材料列表核对（只读）”手动核对名称和内容；相同内容不证明唯一对应本次保存。核对后再显式结束旧意图，重新填写不会自动重发。UNKNOWN仅本页内存；重载页面后先核对材料列表，不能依赖刷新保留原意图。收到保存回执但列表读取失败只需刷新列表。切换“应用”，滚动到“应用草案预览”下的“直接创建 CSV 固定模板草案”；顶部条件报告区不是这个入口。
4. 填名称、目标说明，选刚保存的 CSV，点“创建草案并授权读取”。这一步显式给该应用运行身份有限读取/汇总授权，不授权写入；材料保存与应用授权是两次不同操作。看到草案名称、数值列及清单后再继续。
5. 选择 `amount`，点“运行新预览”，读回 SUCCEEDED、合计 `30`、记录数 `2`。这是 PREVIEW 回执，不是持久 AppRun，也没有发布应用。不要去“项目”的目标框提交自然语言任务代替 CSV 入口。

这些是本人项目内草案和内部版本，没有生成公共网址或外部部署。授权会到期或被撤回；届时按真实授权提示处理，历史记录存在不代表仍有访问资格。

## 人工确认内部版本，创建独立实例

6. 保持预览列为 `amount`，滚动到“内部工程入口 · 只读运行”，点“核查并准备内部快照”。展开“待确认的冻结快照与检查证据”，核对材料、动作、列、检查和指纹。
7. 勾选“我已检查上述精确快照；仅保存内部版本，不开通发布或授权”，点“确认保存此内部 Release”。等待操作按钮重新可用及内部 Release 历史出现。
8. 在这个 Release 的历史行点“创建独立实例”。等到实例 ID、Release、revision 和“冻结材料的数值列”出现。这只创建内部实例，不是部署。

核查不是“确认所有目标都达成”；有限工具样本 PASS、目标语义 NOT_RUN、用户确认 PENDING 和正式发布关闭须分别看待。

## 运行新输入，辨认本次结果与历史

9. **在下方“冻结材料的数值列”再次选择 `amount`**，点“提交新持久 AppRun”。这一列与上方预览列是两个表单，预览选择不会保证下方参数相同。先等待已接受的 Run 与 SUCCEEDED，再点“重新读取内部历史”。读到新 Run、结果 v1、`amount=30`。
10. 等当前操作完成、按钮重新可用后，在同一实例的“冻结材料的数值列”选择 `quantity`，再提交一个新 AppRun，等终态后回读。应得到**不同 Run ID、结果 v2、`quantity=15`**，v1 的 `30` 仍留在历史。这里的新输入只是同一冻结 CSV 的另一数值列；没有更换材料。
11. 刷新整个页面，重新输入原令牌连接，选择原项目，进入“应用”顶部的“使用已保存的本地应用”。点实例行的“使用此本地实例”，查看“运行与结果历史”中的 v1/v2。回读/刷新是只读，不点击“运行此本地应用”就不会提交新任务。要确实运行第三次时才选择本次数值列并点该按钮。

在该实例的历史中点“查看这次运行”，核对 Run ID 和结果版本；成功且结果谱系可核对时，可明确点击“下载此运行结果 JSON”。每次下载重新读取该 Run 并核对当前权限和版本，只包含实例、Run、Release、结果版本及 resource_id/column/sum/count，不含原 CSV、合同或令牌；sum 保持原字符串精度。下载本身不运行任务或新增授权。下载期间换身份、项目、工作区、实例或所选 Run 后，原响应失效，需要在当前选择重新点击。此入口的合成 HTTP/DOM 工程证据不代表真实浏览器落盘或 PostgreSQL 四步体验已通过，见 [本轮记录](F2/CsvRunResultDownload20261016.md)。

浏览器关闭不取消已接受后台任务。QUEUED/RUNNING 时旧成功只能当历史，不能当这次成果；失败的新 Run 也不能借旧成功说明本次通过。刷新后数值列可能默认回到首列，每次新提交都亲自核对。回执未知用本页明确的“用原请求键恢复提交”/“恢复接受回执”；已接受但详情读取失败只用回读按钮。不要用另建实例或反复新提交代替恢复。刷新丢失页面内原键时先读取已保存历史，确认原任务。

已有的字面文本应用也会列在同一“使用已保存的本地应用”目录，标为“文本字面检索”。点击“使用此文本检索应用”后重新核查授权，明确选择一个已保存实例，填写本次检索词并点击“提交新持久 AppRun”，再读取后台任务与结果历史。它固定已授权的 TXT/MD，每次对新检索词重新计算完整匹配行，运行不调用模型。页面重开后重新连接、选择原项目和应用，再打开同一实例可回读各结果版本；目录与打开动作均不自动创建实例或运行。每条成功历史结果旁可点击“下载此检索结果 JSON”，重新核查该 Run 的授权和成果版本后导出实例、Run、Release、结果版本、材料修订/哈希、检索词及完整匹配行；无命中导出空引文数组，语义仍为 UNKNOWN。人工签收须单独核查，正式发布仍关闭。该入口的合成 HTTP/JSDOM 工程测试不代表 PG、真实浏览器或 Windows 已验收。

检索词输入统一显示“当前码点数/80”。BMP 字符和单码点 emoji 都按一个码点计算，组合字符可能占多个码点。粘贴超限文本会完整保留，请修改后再提交；输入法组合尚未结束时不会建立新预览、样例批准或运行。已有原请求的恢复继续使用其冻结输入，不读取新草稿。真实浏览器输入法与剪贴板体验仍待验收。

已有的 `closed-text-four-step.v1` 应用也列在同一目录，标为“四步文本流程”。点击“使用此四步文本应用”，明确打开一个已有实例，填写两个检索词并选择是否生成报告，再点击“提交新持久 AppRun”。固定 TXT/MD 限 1536 字节、32 行，两词各限 80 码点；运行复用原四步控制器，不调用模型。报告选中时核查完整引用并保存新结果版本；未选时保留三个已执行步骤和报告跳过回执，当前 Run 为 PARTIAL、没有新结果，历史成功仍可回读。页面重开后可从目录找回同一实例、Run 和结果。人工状态仍为 PENDING，此类型暂不提交人工声明，语义 UNKNOWN、正式发布关闭。其他未知文本图或 CSV DAG 不经此四步入口打开；此入口的合成 HTTP/JSDOM 测试不能代替 PG、真实浏览器或 Windows 验收。

## 复用已保存的 CSV 流程

“使用已保存的本地应用”目录现在分别列出“CSV 单步汇总”和“CSV DAG”实例。DAG 行标明读取→求和、读取→求和→报告、读取→双求和或项目固定报告版本；点击“使用此 CSV 流程实例”仅重新鉴权、核对原图和版本并读回已有实例，不创建实例或运行。选择冻结允许的数值列，另行勾选运行确认，再点击原流程运行按钮；Worker 完成后手动读取，查看同一 Run 的完整步骤证明及结果版本，冷页面可从目录找回历史。所有执行继续走原 canonical 图、授权、版本及 typed 结果合同，0 模型请求，内部未发布、语义 UNKNOWN、人工 PENDING。未知图或版本没有可运行入口；条件跳过图仍属于原任务范围，不能因本入口变成可保存的内部实例。两步和普通报告的前序验收见[目录接入证据](evidence/csv-dag-directory-20261017/README.md)；双求和与项目固定报告的目录闭环范围及实际结果见[后续目录核验](evidence/csv-dag-directory-dual-fixed-20261017/README.md)。合成 HTTP/JSDOM 证据不代替 PG、真实浏览器或 Windows 验收。

双求和实例分别显示两个稳定节点的数值列选择；任一列修改都会撤回旧运行确认，两份结果按节点 ID 保存在同一次结果版本中。项目固定报告实例起始显示已批准的默认列，也可明确改选冻结允许的另一列；无需先打开旧项目修改键页面。请按完整实例 ID 选择目标，别把目录或下拉首项当成自己的选择。每次新 Run 的输入、Release、结果版本和证明须对应；冷页只读找回同一实例与原 Run，不会重做任务。

每条成功历史成果旁可明确点击“下载此流程结果 JSON”。下载前重新读取该 Run 并核查当前权限、对应内部版本和成果记录；文件保留实际 Run 与 typed AppRun ID、实例修订、Release/来源指纹、输入、结果版本、完整聚合节点输出及同 Run 报告，数值合计保留字符串精度。读取节点中的原 CSV 内容、授权合同和令牌不进入文件。点击另一条历史成果下载、切换身份/项目/工作区/实例或刷新结果后，旧下载响应失效，需要在当前选择重新点击；撤权会清除受保护结果。下载不创建任务、授权或新结果版本，仅交付成果 JSON，不是应用包导出。工程测试使用合成 HTTP/JSDOM Blob 捕获，不能代替原生浏览器落盘、Windows 或 PG 验收。

同一应用已有兼容内部版本时，可在下方版本采用区域明确选择目标，核查来源、目标、实例修订和保留结果，另行确认采用。核读后的版本下拉显示该实例当前版本；新运行仍需重新确认输入。采用后冷页打开同一实例，旧成果下载保留旧 Run 自己的 Release、修订和来源，新成果绑定新版本；不会把旧成果改签为当前版本。撤回所需授权后，新旧成果均不可下载。兼容范围仍按原合同限制，详见[兼容版本切换](F2/CsvDagVersionSwitch20261011.md)。

同一草案的“固定 CSV DAG”面板现有一个独立的[两步流程内部版本入口](F2/CsvDagInternalReuse.md)。在“有限节点组合”只连接读取和一个求和节点，保存精确计划并人工确认执行；来源必须真实完成两步并核验成功。在“两步流程内部版本”区域依次准备来源、核对冻结来源与允许列/预算、显式保存版本、创建独立实例；这些步骤不会自动继续下一次写入。

在该区域选择冻结CSV的另一数值列，单独勾选运行确认并提交。读回不同Run ID、两个真实回执及持久结果版本后，关闭页面并重新连接原项目，可从“使用已保存的本地应用”目录选择此流程的精确实例，只读恢复既有Run与结果；再次确认新列才会建立新Run。

接受回执未知时使用本页保留的原键/原请求恢复；已经取得接受ID后只重新读取。页面重开会丢失未确认的页面intent，先只读核对已保存历史。本次Run输入固定同一材料，不能换接线或添加条件/报告节点；兼容版本切换另走已有的核查与明确确认，不会自动切换或开通发布。材料保存UNKNOWN仍无幂等键，不能借这个新入口自动重发材料。

## 需要用另一份 CSV 时

本地应用实例固定材料；换列不是换材料。受限 P-B 路径是“成功 CSV AppRun → 保存可复用草案 → 绑定同项目另一份 CSV 的**已有授权应用** → 再确认内部版本、建实例、新 Run”。先保存不同内容 CSV 并创建目标初始应用，再按 [RegisteredRunQuickstart](F2/RegisteredRunQuickstart.md) 操作。提取不会自动增补授权，来源失败/未知、撤权、版本冲突或空目标会拒绝；不是把来源答案复制成新结果。

命名条件报告/Report Manifest 是另一条有限资料与显式假设路径；默认 provider 未配置可能 WAITING_RESOURCE。本次指南不激活它，不规避 PG 报告计时门，也不将 CSV 路径通过当作报告或完整 P-B 验收。

## 开发者复核本次路径

普通用户体验不需要 Node/JSDOM；以下只供开发者核查页面事件与真实持久结果，不能代替原生安装。

在已安装项目依赖的隔离 Python 环境，以及能解析 `jsdom` 的开发 Node 环境中，从仓库根运行：

```bash
PYTHONPATH=src NODE_PATH=/你的开发工具/node_modules python scripts/first-use/offline_verify.py --output /tmp/first-use-result.json
```

Windows 开发者的等价环境设置为 `$env:PYTHONPATH=(Join-Path $PWD 'src')`、`$env:NODE_PATH='<自己的开发工具node_modules>'`，用仓库 Python 执行同一脚本；这个等价命令尚未 Win11 实测。脚本不会安装依赖、读 `.env`、接受真实 DSN/令牌或开通 provider，只创建自己临时 SQLite 测试库和固定合成身份，起自己的 loopback API/正常 Worker，完成后停止线程、删除临时库。它会保存新生成的合成 ID/结果及失败阶段，不输出凭据。缺 Node/jsdom 为 BLOCKED；真实 API/worker/JSDOM 断言失败为 FAIL；浏览器/像素/Win11 保持 NOT_RUN。

## 已保存目标卡的普通任务入口（新增有限能力）

在已有正常API/worker和项目授权材料的环境中，打开“项目”下的“目标卡与验收草案”，填写目标、已知、假设、未决项、硬条件、验收项并选择已授权材料，保存后重新打开该卡。确认保存版本，点击“按已保存 vX 执行任务”。按钮执行的是保存版本；刚修改但尚未保存的字段不会参与。接受后读当前任务与实际材料回执，刷新后从普通“任务历史”定位原Run。未知回执用原键恢复，已接受但读取失败只重新读取，不另建任务。

当前默认MOCK只验证请求/工具接线，普通结果仍PARTIAL、目标验收NOT_RUN，未生成应用候选。它不能替代上面的CSV模板求和流程，也不能证明真实自然语言规划或目标达成。新增步骤仅完成本地实际HTTP/DOM与正常Mock Worker验证，原生像素/空环境安装/PG并发/Win11未测；[范围和失败历史](F2/GoalCardRunLog.md)。
