# 已保存的完整 CSV 报告流程

在普通任务的完整 CSV 报告成功后，点击“核查完整报告流程”，核对来源、三工具流程及版本，填写名称并另行勾选保存。保存对象是不可变的 `csv-full-report-workflow.v1` 配方，在同一“应用”目录和“使用已保存本地应用”列表中归为“完整CSV报告流程”。它与单步 SUM_ONLY、CSV DAG 摘要分开显示，不冒充内部 Release 或实例。

打开流程，明确选择当前项目已授权的 CSV 和数值列，再勾选“准备独立完整MD合同”。这一步只保存新的普通 Run，状态为 `WAITING_APPROVAL`。明确打开该 Run，核对新来源/hash、列、数值规则、记录数、精确合计、完整 MD 预览、保存与回读要求，再另行确认执行。结果、完整合同和 MD 下载沿用同一 Run 的现有成果画布；目录保留各次 Run 的入口。

每次使用重新生成材料绑定、完整报告文本/hash、限额和期限，执行原 `resource.read@1 → data.aggregate_csv@1 → artifact.save_text@1`，在同一 Run 验证完整报告的保存及字节回读。新报告不读取旧结果作为答案。来源只接受原普通完整 CSV 合同实际成功的 Run；本版本不递归提取流程产生的 Run，也不接受仅求和应用或人工签收来替代完整报告来源。目前来源限于既有 mock 合同工程路径。

保存流程和准备新 Run 不创建执行身份、工具或写入 Grant。使用当前项目原 runtime，重新检查本人及该 runtime 对旧来源、原完整报告、新 CSV 的所需权限，以及项目既有 `artifact.save_text` 授权。实际保存沿原工具政策新增一个 MD Resource 和两条成果读取 Grant。新定义、请求指纹、流程版本和 Run 合同的关联与接受同事务落盘，并由独立关联行、事件、Run 标记共同核验；GET、确认、Worker 领取和执行在正文前核查当前来源及权限。

重复点击只发送一次 POST；同 key 同正文返回原接受回执，改正文拒绝。响应丢失后，仅 GET 原 key 恢复；切换账号、项目、工作区或应用使迟到回调失效，不自动打开 Run 或执行。当前页面保留待恢复 key；不声称浏览器进程重启后恢复内存中的待提交选择。

完整结构化合同可以独立得到 `PASS_CSV_REPORT_CONTRACT`。通用语义仍为 `NOT_RUN`，人工为 `PENDING`，正式发布关闭。本流程没有新增完整 MD 人工声明协议，SUM_ONLY 的人工接受不扩大到完整报告。

既有数据库需要按现有运维方式显式迁移，仅增 `csv_report_workflows`、`csv_report_workflow_uses` 两表；API 和 Worker 不自动迁移。本轮只在自有合成 SQLite 中验证，未操作真实数据库或授予数据库权限。

验收仅为合成数据、实际 ASGI/SQLite、拒绝任何模型请求的 Worker，以及加载完整实际页面脚本的 JSDOM 可见控件交互。下载验证使用现有控制器创建的 Blob 和文件名，未启动操作系统下载。PG、Windows、原生浏览器、真实模型/语义场景、独立进程重启、远端 CI、部署及真实旧用户数据库未执行。既有满盘丢失的独审文件不因此补回。
