# Accounted Generate/Source family — bounded consumer and fingerprint review

Decision: **BOUNDED_CLOSURE_IDENTIFIED / DESIGN_ONLY / NOT_READY_RUNTIME**.

The requested family has a bounded migration seam across four runtime modules plus the three fixed model schemas. It does not require migrating every Cold fact or the whole platform. Freezing only `_graph_stage_accounted`'s returned/raw value is insufficient: stage tuples, complete-graph copies, typed cohorts and archive consumers still retain/read the original objects. The closure below must change together, while unrelated graph roots and all current authorization/DB/commit gates keep their original protections.

Baseline HEAD `f814843a1ce776c8cdc6387352650b743f8ca0d2`; initial status empty. This reviewer only read source/test source and wrote this `/tmp` report. No product imports, tests, profile, fixture, DB open/decompression, Mock/model, launcher/G0, signals or repository writes. The proposed `/tmp` frozen-graph prototype was not provided or executed in this review.

## 1. Exact issued shape and producer obligations

`pa_trial_dispatch._graph_stage_accounted:1569` returns `(run, actual, chains, ns_reads)`:

* `run`: complete selected `runs` row. Current columns are `id,project_id,principal_id,runtime_id,goal,resource_refs,status,request_key,fingerprint,created_at,lease_until,fence,worker_id,context,result,error,cancel_intent,version`.
* `actual`: ordered complete `attempts` rows, `ORDER BY created_at,id`; exactly three Generate or two Source. Current columns are `id,run_id,created_at,mode,request_model,response_model,status,usage,reserved_tokens,parameters,response,error,elapsed`. Preserve nested JSON, null/absence and exact scalar/sequence types; do not replace full rows with the subset used by one leaf.
* `chains`: one ordered `(Slot,Capture,parsed,checked,wire,payload)` per actual Attempt. `checked` is a separately fetched complete Attempt, not an aid-only DTO. `wire/payload` are exact immutable bytes. `parsed` is the complete strict-parsed response tree, not just usage/canonical evidence.
* `ns_reads`: Generate has `()`; Source has two `(aid,request BodyArchive,wire,response BodyArchive,payload)` entries. Preserve every entry, ordering and multiplicity; the Source chain and NS raw byte pairs must agree exactly.

Producer sealing can happen only **after** its original whole proof completes, not after the first successful chain. The producer retains `_journal_stage_header` current scope/phase gates; full journal state/cursor proof; actual stage count and version/account/trial/approval markers; complete Run SELECT; slot/aid multiset; per-aid `_graph_journal_chain` ownership/header/body pair/seal/metadata/policy binding/approval/slot identity/capture/raw canonical/Attempt checks; known usage and settlement; and Source's ordered NS `_read` pair/seal/anchor/provenance/raw-byte checks plus VERIFIED Operation SELECT. A packet never substitutes for those reads or issues send authority.

The two same-aid reads (`actual` and chain `checked`) and all three/two chains are meaningful independent relations. Do not silently collapse duplicate ids, equal-valued objects or different rows in the packet builder. Current producer validation/counts plus explicit association proof must remain.

## 2. Complete fixed model projection

All current fields, including defaults and `None`, enter the existing complete raw shape. Required leaf schema closure is small:

| Model | Complete fields and nested closure |
| --- | --- |
| `policy.Slot` | `identity,reserved_at,attempted,settlement,accepted`. `ReservationIdentity`: `requirements_fingerprint,approval_fingerprint,stage,stage_fingerprint,run_id,runtime_id,version,fence,worker_id,account_id,quota_subject,attempt_id,wire_sha256,wire_bytes`. `Outcome`: `outcome,response_sha256,response_ascii_bytes,prompt_tokens,completion_tokens,total_tokens`. |
| `sender.Capture` | `provenance,raw_sha256,raw_bytes,body_b64,complete,received_response,omission,canonical_sha256,canonical_ascii_bytes,response_verdict,outcome`; nested `Outcome` as above. |
| `archive.BodyArchive` | `version,run_id,attempt_id,principal_id,project_id,runtime_id,phase,provenance,byte_count,sha256,received_complete,extent,omission,body_b64,canonical_sha256`. |

An owned packet may use tagged immutable records rather than retaining these Pydantic instances. Admission must prove the actual exact-type/nested storage and full schema, not merely call a coercing constructor on a mutated model and treat normalization as proof. Preserve bool/int/float and list/tuple distinctions where the current typed contract checks them. No foreign mapping/key/equality/serializer/reducer callbacks; no live model/RowMapping/dict/list/closure reference in a completed packet. Trusted SQLAlchemy `quoted_name` keys require a controlled exact-class projection and duplicate-after-normalization check; ordinary string keys and arbitrary subclasses are different cases.

The existing serialized family shape (`gate._graph_trial_accounted_raw:1535` and runtime `_accounted_fields:2567`) uses `dict(row)` for run/actual/checked. The separate `_trial_pure_mapping(RowMapping)` path also checks native row metadata before producing visible pairs. Therefore “all semantic business columns copied” and “all hidden raw storage retained” are distinct claims. To follow the ACKed parent design's conservative first step, admit/check and own the complete controlled keys/data/safe-index projection as an immutable sidecar, with a complete business-value view; never carry live metadata. This is a bounded migration choice, not a V5 mandate to preserve irrelevant driver layout or a reason to migrate the global row codec.

## 4. Fingerprint/data flows and compatibility

1. **Local continuity only:** producer raw `cold-trial:accounted-source/generate` and `complete.source/generated` enter `_ColdGraphRead.input_bytes/key`; typed cohorts compare against those shapes. A new private version may represent the owned family differently, but scope/role/phase issuance must be non-forgeable, every alias occurrence must refer to the correct packet, and the final complete manifest must bind full content. No caller-supplied digest is trusted. Keeping large bytes embedded in every old full hash may retain most of the byte-copy cost; the closure identification is not a measured speedup.
2. **Persistent archive fingerprints:** NS `_read/pair` retain request/response sealed record fingerprints; `_body_payload_from_facts` requires exactly one NS event anchor `fingerprint(body.model_dump())`, complete body/extent/omission, byte length/raw SHA and exact base64. Sender `_captured` loads the original CAPTURE pair under `_capture_request(identity.model_dump(mode='json'))`, checks frozen mode/provenance/derived capture/outcome and original persistent pair fingerprints. These original encodings and payloads must remain byte/field compatible. Do not hash packet tags/node ids with `db.fingerprint` as a substitute.
3. **Raw versus canonical:** raw `wire` SHA/size, decoded response SHA/size, canonical response SHA/ASCII size, reservation/settlement usage and preserved received response are distinct. `_stage_source_archive_from_facts`, `_source_exchange_from_facts`, and `_graph_pb_archive_chain` join them. Preserve original hashes/recomputation at their current semantic checks; packet integrity is additional private continuity, not permission to drop raw SHA/parse/accounting checks or turn unknown token counts into zero.
4. **Public receipt:** `_graph_source_bodies` produces ordered attempts containing `attempt_id,request_bytes,request_sha256,decoded_body_bytes,decoded_body_sha256,canonical_ascii_bytes,canonical_ascii_sha256`. `_graph_resolve_trial_source` wraps these with existing trial/approval/source-proof/extraction-recipe/cold-goal fingerprints and source/extraction identifiers. Raw bodies remain in private `ResolvedSourceArchive` tuples; no body data or local node ids enter the public receipt. The later archive-chain proof uses full private bytes as well as this receipt.
5. **Stage authorities:** `_graph_stage_current` first validates full accounted family; actual StageAuthority fields come from `_stage_authority_fields_from_facts` plus current authorization fingerprint and timing. There is no direct `fingerprint(accounted_packet)` authority field in the traced helper. However those validated facts are prerequisites for authority construction; preserving output fields while skipping family validation is not equivalent.
6. **Postwrite/origin isolation:** `_ColdTrialGraph` is also constructed for post phase. Restrict the new family mode to the approved prewrite branch; old post_graph raw/key and apps origin keep the current protocol until an explicit bridge is reviewed. Existing runtime post_graph serialization/key checks and any software/audit anchors must not accidentally receive a packet-digest substitution.

No direct persistence call using the whole accounted raw family was found in the traced path. This is a bounded static finding, not a proof that all future or external consumers ignore it. Keep the local protocol selection explicit and persistent fingerprint algorithms unchanged.

## 5. Prototype criteria and necessary offline counterexamples

The proposed per-call active/done memo plus immutable flat node table is suitable for **offline representation exploration**, not yet a production candidate. It must:

* reject active backedges/cycles before publishing any completed node; memoize only completely built nodes, only inside the same freeze call; validate the exact input type before any memo shortcut;
* expose an immutable root/table with no mutable builder, raw source, Pydantic/RowMapping or closure escape; enforce existing type/depth/size limits; keep root/family/stage/schema domain tags;
* preserve every array edge and order/multiplicity even when completed DAG nodes are shared; flat encoding must use node references rather than recursively expand repeated subgraphs. State complexity as **O(V+E+B)** including emitted byte/string payload; do not hide large raw bodies behind an O(V+E) claim;
* keep local sharing/ids out of persistent business fingerprints. If the private digest intentionally distinguishes shared versus duplicated equal subgraphs, say so; that does not make Python alias topology a V5 business version;
* show positive three-/two-aid complete values; pre-seal mutation/rejection; post-seal original-buffer isolation across **every** aid and nested identity/outcome/BodyArchive/parsed/checked; strict int/bool/float and list/tuple distinctions; missing/extra/duplicate/swap aid/run/role associations; raw versus canonical hash/length mismatch; unknown/None usage remains unknown; unknown key/model callbacks never run; cycles rejected and a deep shared DAG encoding remains linear; cross-call freeze re-reads changed input and cross-scope/role packets are rejected by issuance.

The existing third-aid mutation test `test_cold_trial_guard_delta.py:305` protects the entire cohort, not merely the active first aid. In the new ownership contract, mutating the discarded external model after a complete seal may safely leave the owned snapshot unchanged; a consumer that still reads that external mutation cannot pass. A “pure frozen-shape” test cannot prove current Grant/DB/Operation/source-key freshness or final lease/rollback correctness. Those are retained runtime gateways plus later targeted integration evidence, not a reason to run another business window now.

## 6. Implementation readiness

The bounded seam above identifies which consumers need an owned branch. Still required before any runtime ACK: exact record/node grammar and issuer API, complete family field/view/sidecar map, no-escape proof at each listed consumer, manifest/complete-graph representation and postwrite mode separation, and an old-test-to-new-invariant matrix. No broad removal of `_base`, global typed checks or mutable graph checks is justified: only the fully migrated family can leave that mutable frontier. No performance/G0-pass, PG/real-production, cross-transaction, lease or new-model-window claim follows from this review.
