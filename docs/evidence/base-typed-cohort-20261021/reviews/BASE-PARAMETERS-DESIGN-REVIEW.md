# Base parameter collection: conditional design ACK

Conditional ACK to prepare the minimal default-off native implementation for code review, against clean baseline `f18d6845db4a5ebdb5b71b745462b575cc47cfc0`. This is not implementation, test, budget-change, performance or window approval. The reviewer only read source and searched call sites; no product, DB, tests, Mock/G0, profile or signals were executed and no repository file was changed.

`_typed_parameters` currently has one repository call site, `_ColdTrialGraph._base`. `_base` makes an original exact full CGR check, verifies its worker/connection relationship, collects/checks typed parameters and makes another full CGR check; it invalidates the graph on any exception. The design must keep both complete pins in their original positions and keep the final full `_trial_typed_values(models)` pass.

For the complete native graph with both accounted families and both stage tuples, the 13 nested full checks have a concrete breakdown: two top-level `assert_family` checks; four checks in Cold `assert_stage` plus two in its stage-model family collection; four checks in Source `assert_stage` plus one in its stage-model collection. Earlier/partial construction states do not necessarily have all 13. Removing these internal repetitions must not be described as eliminating mutable validation: each public `_base` call still checks the complete current graph twice and keeps fresh typed storage/cohort validation.

The proposed native branch is reviewable if selected only for exact `_OwnedPrewriteMode`, exact `_NativeCandidate` and `owned_ready is True`, with graph/mode/native/scope ownership checked. Once inside the already pinned lexical segment, one fixed mode helper may run the existing dynamic/frame/link checks, and fixed private pure helpers may perform the original family/Run/stage joins. Family leaf dynamic checks stay in place. Extracting the existing pure stage relation body from `_pin_stage` is preferable to a second divergent predicate copy; `_pin_stage` itself must still retain its original first pin, dynamic/link checks, exception closure and all relations.

The native stage-model collector must preserve the original owned branch completely and in order: input/stage tuple shape, full frozen-model hold from the pinned generated facet, Generate family association, conditional Source family association, and complete extraction equality/hold when present. It must not replace model storage with IDs or omit extraction, hidden fields, revision, context/source observations, source-proof identity, journal parameters, trial/release/use model holds or the final typed cohort. Original gate helpers and public `assert_*` methods must remain independently self-checking.

The direct-call contract needs explicit wording. Because `_typed_parameters` is private with only `_base` as repository caller and returns no permit/value capability, it can be documented as **parameter collection only inside `_base`, not an independently self-pinning validator**. No stack introspection, mutable global flag, skip token, reusable pass or cache is necessary. If the implementation instead promises independent callers the old full-freshness behavior, keep that entry on its old route and introduce a separate private pure collector called only by `_base`. Silently claiming both contracts is unacceptable. Tests of freshness must call `_base`, and the source call-site closure should be checked.

Between the two pins, the new branch must invoke only fixed trusted pure raw/arena operations: no SQL, external/registered callback, model validation or model dump newly introduced before the original final cohort. Original query/return and other boundaries outside `_base` are not exempted. A dynamic/link/association/cohort failure must retain graph invalidation and owned cleanup.

If the actual change only extracts/calls these existing pure bodies and populates the same existing models list with the same triples/order, there is no additional data-size-dependent payload allocation to justify raising allowances. Fixed helper call frames are control overhead. New snapshot/encoding/thaw, copied packet/raw dictionaries, second cohorts, retained comparison tables or new per-node collections would require a fresh budget review and are outside this design. The original complete typed-storage/codec accounting exclusions do not become RSS or CPU guarantees.

Necessary local evidence should compare old vs new complete/partial parameter collection, model hold/cohort sequences and all pure relations; directly count the complete-case internal checks while separately retaining `_base`'s two; reject between-call raw/model mutation, revocation, stop/closed transaction and wrong family/Run/extraction/graph subjects; and preserve default/non-ready behavior and public self-pins. It must not use a faster first commit, a sub-30-second wall duration or local call counts as a complete G0/final-deadline result. Actual code/diff and stable-hash author evidence remain for the next review.
