# Optional fresh C typed visitor: initial design review

Baseline read: `a19dff9c5bbca792559905388177618543482dcb`. Reviewer inspected the existing Python visitor and official CPython API/source only; no build, product import, test, DB, Worker, Mock, profiler or G0 was executed. No repository edit or new runtime authorization.

The proposed optional projection primitive is a plausible next implementation slice because it can retain a fully fresh native clone graph and leave the original C Pickler/protocol and all runtime routing untouched. This is conditional design feedback, not a frozen C-code correctness or production-activation ACK. Default `_trial_typed_storage` must remain the original Python function for this slice.

Required correspondence to `natural_live_admission._trial_typed_storage`:

1. Keep fresh roots then fresh allowed acquisition in original order, root/expected identity checks, exact primitive types and identity returns. Use pointer identity for allowed classes, never foreign type equality/hash. Exact native dict/list/tuple/set checks must not admit subclasses or frozenset accidentally.
2. Preserve active-before-seen, new invocation-specific identity maps, fresh first-visit clone containers, current dict key objects/order, per-source alias distinctions, and two None omissions before visiting omitted children. No model raw-dict merge, shallow snapshot, pool, PASS cache or cross-call memo.
3. Use original iterator semantics, with owned references for each yielded pair/key/child through recursion. List iteration must not assume an immutable initial length or preallocate with an unchecked fixed-length fill: original list iterators can see size changes. Tuple generation remains a fresh result for a first-visited nonempty source; shared source tuples then use seen.
4. Preserve metadata access **and** and-expression order: read raw, fields and selected first; then raw type/key gate, fields type/key gate, key-set equality, selected type/key gate, subset, extra and private checks in that order. The latter two are short-circuited. Calling the original object/type getattribute descriptors is appropriate; ordinary `PyObject_GetAttr` would dispatch instance/metaclass overrides differently. Metadata descriptors can fail or execute code; do not assume they are universally callback-free or move their evaluation.
5. Keep every original failure code/message through the original require function when eligible. Unknown helper qualification selects Python before the action. A native failure must propagate once, not retry the Python copy or rewrite its exception. Failure cleanup must preserve the exception object/state while DECREFing iterators, partial containers and state.
6. The raw C entry point itself must reject malformed API arguments before unchecked access macros, even if the adapter normally supplies correct values. A non-callable or a require callback that returns without raising must not cause invalid casts, NULL-without-error, or continued processing of a failed type predicate. Such ABI misuse can raise a safe Python error; it is not a product acceptance path.
7. Native recursive traversal needs checked recursion entry/leave on all paths and bounded-interval signal checking. Never release the GIL while accessing Python objects. These measures address C-stack/interrupt safety; they do not prove all inputs immutable or reproduce the exact Python recursion failure depth.
8. In CPython 3.12 Python and C recursion accounting differ. Native recursion protection alone does not prove the same RecursionError boundary as the original Python visitor/generator stack. Deep acyclic/cyclic input behavior and its limits require explicit evidence/qualification; do not introduce an unexplained small business depth cap or claim exact deep-resource equivalence from the presence of one C macro.

The official [C API exception documentation](https://docs.python.org/3.12/c-api/exceptions.html) specifies error-indicator propagation and recursion/signal APIs. [CPython 3.12.14 recursion internals](https://raw.githubusercontent.com/python/cpython/v3.12.14/Include/internal/pycore_ceval.h) show the C recursion counter. These support the implementation cautions, not a claim that source alone proves runtime correctness.

Necessary implementation review/evidence includes actual prepared-PB full bytes/aliases against the original visitor, scalar/type/keys/omission/DAG/cycle and metadata short-circuit errors, iterator mutations, exception identity, raw C API bad arguments, interrupted/deep cleanup, and ABI/build qualification. No C candidate has yet been audited by this report. Preserve original Python/runtime defaults and assess actual candidate source before treating the optional primitive as usable.
