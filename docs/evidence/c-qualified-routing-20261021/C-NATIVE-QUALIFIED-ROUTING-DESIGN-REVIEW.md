# Native qualification and explicit routing: initial design review

Only read-only source/official-CPython review. No reviewer product import, C build, test, DB, Worker, Mock, G0, launcher or signal. No repository edits or runtime-window authorization. This report evaluates the proposed design before its selector/wiring implementation exists; it is not a frozen-code or activation ACK.

The plan can potentially narrow the offline native primitive to a proved safe domain rather than pretending its known 1,500-depth difference disappeared. The original helper and default route should remain unchanged. Selection, original per-call clone/pickle, dynamic/SQL/auth/deadline gates and final publication remain separate obligations.

Four concrete requirements were sent to the writer early:

1. The less-than-256 bound must count actual `visit` invocations, including primitive leaves and repeated DAG memo hits, not only distinct nodes. Otherwise the current primitive can still reach its periodic `PyErr_CheckSignals` after the qualification proof. Scanner metadata/key/MRO/selected work needs its own finite work limit.
2. Same standard metaclass identity is insufficient by itself: a metaclass-MRO data descriptor can take priority over a class's own fields entry. Static qualification must establish the effective lookup for that class metadata as well as the four instance storage descriptors. Unknown property/getter/finalizer code must select Python before invoking it.
3. A Python selection sentinel should return to the original `input_bytes` caller frame before invoking the old helper. Calling that helper from inside an extra Python adapter frame shifts its critical Python recursion boundary. Native qualification may conservatively reject, but fallback should not unintentionally add a deeper helper call stack.
4. “Qualification errors choose Python” must mean known unsupported representation/capacity/budget. Original signal BaseException, MemoryError and unexpected internal C errors must not be cleared and retried through Python. Once native projection starts, failure still propagates once.

Official [CPython 3.12.14 gcmodule.c](https://raw.githubusercontent.com/python/cpython/v3.12.14/Modules/gcmodule.c) shows `_PyObject_GC_Link` scheduling collection through gc_scheduled/eval_breaker. [ceval_gil.c](https://raw.githubusercontent.com/python/cpython/v3.12.14/Python/ceval_gil.c) processes that scheduled collection in the eval pending handler. This supports a narrowly audited no-evaluation C interval; it does not establish that arbitrary C API calls cannot execute Python, that source objects are globally immutable, or that entry `PyErr_CheckSignals` drains all GC/pending calls. The appropriate claim is no pending-handler execution point between the fresh scan and copy, after separately allowing entry signal handling to finish.

The actual C selector must prove its complete call inventory: static type/MRO/namespace inspection before getters; exact native containers and controlled fixed storage; no foreign hash/equality, descriptors, `repr`, callbacks or allocation-finalizer effects; no GIL release or interpreter evaluation between qualification and projection; fresh recursion budgets read after entry callbacks; correct path/generator/helper margins for the precise interpreter/build. The graph scan is qualification, not a remembered PASS, and cannot skip any original copy/gate. A bounded array needs explicit capacity checks before every push/write and strong-reference ownership where necessary.

Exact runtime/build/SOABI/executable/header/source/backend provenance and no default backend discovery are appropriate declared qualification goals, but their implementation, cost and failure semantics are not yet reviewed here. Explicit attachment must remain restricted to the requested test-only SQLite worker and original graph construction points; it must not replace the helper identity and silently force the base into legacy routing. No new source account, lease or authority follows from a backend attachment.

No unconditional implementation-independent blocker was established for a correctly closed narrow selector. The listed points remain implementation proof obligations, not statements that the proposed code has passed. Actual source plus qualification counterexamples, net component cost and original semantic-chain evidence should be judged in that order without using the design review as execution approval.
