The old Worker only recovered PROJECT CHECKs. Ordinary claim never selects already-RECONCILING runs. Generic attempt reconciliation only accepts STARTED and refuses unresolved operations, so neither entry could close the received Cold model operation.

The default Worker now runs a bounded, round-robin receipt-only Cold recovery. Historical receipt bodies are checked internally after original owner/control scope, never returned as new execution authority.

Only fully known RECEIVED rows and their uniquely bound DISPATCHED model operations become REJECTED_KNOWN, with the original NS_REJECTED anchor. Response, usage, original reservation, capture, body archives and ledger remain unchanged. A known-but-denied last slot may be closed for cancellation without granting business acceptance: the separate cancellation chain preserves the full original chain, including its late response-metadata read, but does not require slot.accepted. The ordinary business chain is unchanged. The denied-slot test is an explicitly constructed reachable accounting variant of the synthetic input, not claimed as a new real provider run.

After rejecting returned evidence, all history must be known before Run/AppRun become CANCELLED with an incremented fence/version. All writes share one transaction. Missing/unknown/inconsistent evidence, a live owner, scope changes or late callback changes roll everything back, including tentative rejection rows and anchors.

Current-version repeated cancel is idempotent in RECONCILING/CANCEL_REQUESTED/CANCELLED: no new version, event or ownership change. Stale versions still reject. Existing owner/instance controls remain mandatory.
