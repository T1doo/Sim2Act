# V5 freshness boundary — independent design review

Decision: **CONDITIONAL_ACK_DESIGN_ONLY / NOT_READY_IMPLEMENTATION**.

The same-transaction, owned recursively immutable value-packet direction is compatible with the cited V5 requirements in principle. V5 does not make the complete Python helper-object pickle graph, Python object alias topology, SQLAlchemy's unused driver metadata, or arbitrary module monkeypatch exception ordering a product requirement. This is permission to develop a precise architecture and coverage argument, not approval of an unprovided runtime patch or a claim that G0 will pass.

## Actual review scope

Read-only review of original V5 documents, current runtime/Store/source-read code, and targeted existing test source. No product import, tests, profile, fixture, SQLite/database open, database decompression, Mock, model, launcher, G0 window, signals, network action, or repository write was performed. Only this review directory was written. Initial repository HEAD was `c20b8b6baf2c023b5dc7c89f7e8282bad112f350`; initial `git status --short` was empty. The parent is the sole repository writer. This report is not a complete independent audit of every transitive producer/query field.

## Normative source boundary

* `docs/sources/V5/平台产品设计.md:419–425` (§9.2) requires fingerprints of normalized definitions, relevant upstream revisions, tool/schema/prompt/acceptance versions, actual input snapshots/read ranges, and collection-query dependencies. Unknown dynamic dependencies require conservative collection/project coverage. It expressly requires reauthorization on reuse and excludes data/permission/release decisions based only on content cache.
* Lines 347–399 (§8) require lease/fence exclusion, current authorization before dispatch, local data and receipt atomicity, approvals bound to exact request/release/resource/precondition/identity/expiry/auth revision, and revocation enforcement across cache/old-run/alternate-entrypoint reuse and before visibility. A packet is never an authorization decision.
* Lines 450–466 (§10) distinguish immutable release definitions from mutable business state and require dynamic authorization per action; execution is through the trusted registry, without model-supplied executable code or new executors.
* The plan's AT03/04/06/08/10/11/12/14/18/20/21/22/25/26 require fail-closed validation, private-read barriers, fence/revocation coverage, independent new execution, complete dependency accounting, consistent public/internal entrypoints, and independent acceptance. Replacing an implementation oracle must not silently reduce those outcomes.

These requirements justify changing a private continuity representation if the business semantics and security boundaries are demonstrated. The previously noted `runtime.tuple` monkeypatch counterexample is a valid difference for that old helper's unrestricted Python execution semantics; it is not by itself a V5 prohibition on an explicitly redesigned trusted packet boundary. Injection tests that model actual revocation, cancellation, data changes, or deadline passage remain substantive even when they use monkeypatches.

## Current path and compatibility limits

1. `natural_spec_runtime.py:2936` selects this special path only for exact PB trial binding/contract, `store.test_only and store.sqlite`, the current second resource/runtime relation, and an existing transaction. The broader application and PB paths have fallback implementations. This proposal is initially a **test SQLite G0 branch** design, not a PG or real-production qualification.
2. `db.py:726` opens SQLite `BEGIN IMMEDIATE`. Keeping that transaction preserves the existing write-transaction boundary but also keeps its writer lock. This design neither releases that lock nor establishes how long a background heartbeat was blocked. It supplies no 30-second/G0 performance guarantee.
3. `_ColdGraphRead` currently binds connection, transaction, driver, changes, source-read token/epoch, thread, scope nonce, binding/configuration/worker state, and complete mutable inputs. `check/add` perform repeated whole-graph continuity checks. Ownership can replace the mutable-value part only after the input/consumer map closes; transaction/phase/current-control checks are a separate requirement.
4. `_ColdTrialGraph.commit` has a first semantic construction/validation gate and a second live recheck gate. The latter repeats approval/source/authority/full Run checks. `_cold_model_before` checks finite deadlines and stop again **after scope closure and immediately before the original write group**. `_ModelSettlementRead.live/settle/tail` retain postwrite reauthorization, complete Run/context/fence/expiry checks and final finite bounds. All remain required in this design.
5. A global codec replacement is out of scope: `apps.py:105` uses `_cold_graph_inputs` for origin continuity; runtime `3308–3312` places complete graph bytes and `guard.key` into `post_graph`; `_ModelSettlementRead.check` compares that key with the live graph. A new private domain/version must have an explicit bridge for each affected ephemeral consumer. Persistent approval/request/source/release/business/receipt fingerprints and historical evidence keep their current meaning and version.

## Conditions to close before a runtime patch can be approved

1. **Complete producer/consumer inventory.** For each fact family name its producer, original authorization sequence, actual SQL query and full selected-column/schema coverage, runtime/role, phase, returned fields and every later consumer. Include contract/roles, complete Run/context, binding/release/snapshot/approval/authority, source and extraction facts, journal ledger/cursor, all accounted attempts/archive request and response bodies, slot/capture chains, and postwrite proof. `_ColdTrialGraph._fields` and the post-graph bridge are starting points, not a proof of completeness. No fallback read from a retained mutable raw object after sealing.
2. **Controlled admission and real recursive ownership.** Validate at a trusted entrypoint, copy all business values, and seal a closed exact-type value grammar. Exact immutable atoms/bytes and recursively immutable tagged sequences/map entries are suitable building blocks; enforce finite numbers, exact numeric/sequence kinds, field/null/absence distinctions, and current size/depth limits. A frozen Pydantic model, frozen dataclass containing mutable members, or MappingProxy over a mutable dictionary is insufficient. Do not dispatch arbitrary mapping, deepcopy, reducer, descriptor, instance serializer, or key equality callbacks during admission. Reject cycles and unsupported types before issuance. Private factory issuance plus scope/generation/role/phase identity must prevent forged or cross-scope packets.
3. **Separate semantic facts from live authority/control.** Each original producer still authorizes before private reads and actually executes the required reads. Existing source resolution, current principal/runtime/project/resource rights, approval and revision checks, stop/cancel/fence, settings/budget policy and exact finite deadlines cannot become a cached ALLOW. Pure helpers may reuse already owned values within the proven scope; they cannot reuse an authorization verdict. Any source expiry is bounded by a newly observed resolver result and original upper bounds.
4. **Cover mutable storage and read sets.** Immutable packets contain stable object IDs, complete relevant revisions/versions and normalized definitions, plus schema/tool/prompt/check versions and actual query/read ranges. A collection packet must bind query/collection scope and membership semantics, not merely the rows that happened to be returned. Uncertain dynamic access keeps the original conservative dependency coverage. Same-transaction ownership does not authorize dropping collection tracking or persistent dependency records.
5. **Make the scope closed to relevant writes.** Other SQLite connections cannot commit competing writes during this immediate transaction; time can still pass and same-connection code can write. Retain or replace with a proved controlled mechanism the original source-read token/transaction/thread/write-epoch invalidation. Do not infer that a transaction alone excludes same-connection mutation or stale configuration. If trusted producers write a relevant fact, invalidate/rebuild or establish an explicit new phase before any consumer. The prewrite packet cannot simply survive the settlement write group into postwrite proof/G1.
6. **A final digest is integrity evidence, not the freshness proof.** A fresh, domain-versioned full packet-manifest digest before exit may replace repeated hashing of immutable owned values. Its input includes every issued/consumed semantic packet and phase context; no partial manifest or identity-only trust. Cheap boundary checks must establish legitimate issuance and live scope on every required call. Final digest work occurs before the final fresh clock/stop check. Immutability and coverage, rather than a hash comparing with itself, justify skipping rescans. Failure invalidates the scope and rolls back the existing transaction.
7. **Keep both semantic gates and all externally visible effects.** Preserve the two commit gates, source/approval/live authorization semantics, postwrite live/tail checks, original lease/run/approval/source bounds, unchanged write group, receipt/accounting linkage, and atomic rollback. Preserve relevant public domain errors, authorization-before-private-body behavior and absence of unauthorized effects. Exact arbitrary runtime monkeypatch traces are not the criterion. No true-model/Mock execution or new window follows from this review.
8. **Compatibility and rollout are explicit.** Use a new local private packet/digest domain only in the gated branch, inventory `post_graph` and origin interactions, and leave persistent fingerprints and old evidence unchanged. No serialization migration, global codec change, transaction split, cross-transaction reuse, lease extension or new authority is implied. Cross-transaction readset/CAS needs a separate, presently unclosed design.
