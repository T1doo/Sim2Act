# Private fresh comparison: design and rejected implementation

Original full-tail profile, not a new profile: C Pickler inclusive28.091s and typed storage inclusive16.957s are sibling source costs, not additive nested totals. `checked`2271 calls is an inclusive caller count, not removable CPU. No unsafe parent/child PASS inheritance was implemented: `_prepare` retains rawA from `_graph_trial_produced` and separately creates rawB via `_dump`, while recheck produces new models/SQL outputs. Mutating rawA can leave parent rawB valid. Audit/codec callbacks also interrupt a purported pure segment.

The implemented candidate instead tested full fresh structural comparison. Original `_Frontier.expected` is private continuity state, not an origin/business fingerprint. Its optional immutable baseline could therefore preserve source type/order/full alias relations without preserving pickle-injected marker/module objects. All legacy byte exports still used the original protocol and fresh memo. This is an explicit private continuity contract, not a claim of pickle byte equality.

Memoized str/bytes/container/row/Limits relationships were normalized over the whole envelope. Int/float/bool/None and empty tuples did not gain artificial identity requirements that the original protocol does not encode. Float comparison used exact big-endian double bits. Adapter temporaries were held strongly during a traversal to avoid ID reuse. No mutable container/model/RowMapping survived into baseline records; immutable strings/bytes could be retained. Completed memo was invocation-local, after the active cycle check.

Future-root growth has no proven global bound under existing unrestricted JSON/DAG sources; an upfront whole-capability bound cannot be invented. This implementation selected a bounded verifier per call while retaining original expected SHA and owned capability routing. Its private independent selection budget could stop without invoking owned `_Ledger.on_failure` (which closes the graph). A partially completed selection was never treated as a successful verifier. A selected comparator exception/mismatch never retried. On unsupported layout the original verifier still owned acceptance/rejection.

Capacity described one optional projection construction. A baseline plus current scratch, or initial capture plus fresh publication self-comparison, were bounded by twice that limit. Original PB projection/SQL/codec allocations stayed original work. There was no RSS/CPU/process claim or business input cap. Every exact added edge invalidated the prior baseline; old roots were rechecked before adding it to the baseline domain. Before publication the captured snapshot was checked by original SHA and then compared to a fresh whole-envelope snapshot, avoiding a transient B→A endorsement.

The experiment was safe enough for one bounded synthetic comparison after independent static review. It was not fast enough to earn adoption: the full experiment hit the existing300s test helper and could not publish candidate observations. No full candidate timing or exact-output equivalence was recovered afterward. Both product implementation and supervisor option were withdrawn.

CPython's [official pickle documentation](https://docs.python.org/3.12/library/pickle.html#comparison-with-marshal) explains why shared objects and a whole-graph memo matter. That documentation supports the alias design requirement, not the candidate's equivalence or performance. The local exact CPython3.12.14 opcode checks distinguished memoized strings/bytes from scalar ints/floats and empty tuples; no pure-Python Pickler stand-in was substituted for production C Pickler.
