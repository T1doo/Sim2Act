# Configured synthetic tail under a test virtual clock

CONDITIONALLY_IMPLEMENTABLE_TEST_DESIGN_ONLY. This is not a harness/code ACK, a real-time G0 performance claim, or a new execution authorization. The parent's explicit current authorization supplies the test scope; this note only reviews the design. Reviewer executed no product/test/DB/Mock, launched no process/window, sent no signal, and wrote no repository files.

The proposed original configured prefix plus two positive Cold1 arms and up to five negative Cold1 cases can supply stronger actual coordinator/receipt/normal-scope semantics than the current lower-level fixture. Keep the original three configured engineering substitutions expressly SYNTHETIC; do not promote them into production account/source/software qualification. Freezing a test wall clock during G0 exercises original finite predicates under controlled time, but deliberately removes elapsed real computation from those predicates. It therefore cannot close the historical real-time lease/G0 acceptance failure or prove a speedup.

Clock conditions:

- Advance virtual time only through the designated original journal-wait scheduling boundary. Never jump a full 60 seconds and renew afterwards: advance to the earliest due original heartbeat wake first, block foreground progression at that virtual instant, and wait for the real Store.heartbeat transaction to return committed before advancing farther. Preserve original failure/fatal/stop observations and publish no synthetic renewal success.
- During G0, virtual time remains fixed and a background heartbeat must not independently advance it or manufacture lease progress. Preserve original synchronous renew, lease=30, Run=300, TTL=1800, source/contract deadlines and all business clock callsites. No database timestamp rewriting, expiry rebasing or lease extension.
- Keep real monotonic scheduling/watchdog/cleanup references saved before patching. Test scheduling deadlock or missed heartbeat commit must fail with a bounded real timeout and UNKNOWN/incomplete evidence, not wait indefinitely or count uncommitted heartbeats. Event.wait replacement must be limited to exact registered original business-wait/heartbeat Events and known code roles. All other Events, Thread start/join machinery, condition variables, clients and cleanup retain their original real waits. Thread join returning is not proof of thread exit; independently check is_alive/owned thread closure.
- Run the test clock in an isolated fixture/process with no unrelated concurrent tests using the patched global time module. Clearly record clock origin, each scheduled advance and committed-renewal acknowledgement. Virtual business duration, actual monotonic duration and logical/real Mock counts are distinct measurements.

Snapshot/differential conditions:

- Complete original G3/S2 prefix, Cold queue and explicit phase approval, then quiesce all prefix workers/heartbeat threads, clients, connections and pools. Make a consistent SQLite backup, or copy a fully closed database including any required sidecar state; copying only the main file while WAL is live is insufficient. Freeze and hash the template. Each arm/case receives a separate owned directory, new database, Store/pool and Worker; never write back to the template.
- Preserve all stored identities, approval/source/Run timestamps and fingerprints by byte/value; restart the virtual clock at the identical captured template instant for each case. Do not silently rebase old timestamps. Old/candidate positives use identical source state, configured responses, protections and stop boundary; identify the old policy adapter as an algorithm adapter on the same frozen source, not a claim of executing a different historical source version.
- Isolate state outside SQLite too: binding.contract models, configured revoked flag, sends/workers lists, current transport, stop Events, schema or registry mutations and monkeypatch contexts must not leak from one case into the next. Rebuild case-local model/closure state from the frozen template. A suite-global accounting ledger may only accumulate actual attempts; do not share mutable business state.
- The real suite cap is 5 shared-prefix exchanges + 2 positive Cold1 exchanges + at most 5 negative Cold1 exchanges = 12 exchanges, with the two Source delegate method entries giving 14 methods. Each case's logical combined path is at most 6/8 including its shared-prefix provenance. Failed attempts count; no automatic replacement runs. Hard reject any unexpected Cold2/model request before transport dispatch. Each cloned DB must contain only its intended queued Cold task, avoiding another queued job consuming the case budget.

Stopping/oracles:

- Positive completion means real original prepare, both real commits, receipt continuation, original context exit and its final clock check returned normally. Only then raise the dedicated BaseException before the next W5 statement. Preserve original rollback/finally behavior and prove owned threads/clients/connections closed; do not label interrupted-before-W5 Run/Attempt state as finished business acceptance.
- Negative cases require their exact injection point and original refusal, no normal context completion, no W5/Cold2, no hidden resend, and appropriate preserved response/accounting evidence. A StopBoundary signal by itself does not make a negative test pass. No negative arm may inherit damage from an earlier case.
- Compare complete semantic fields, ordered SQL/parameters as applicable, original at/deadline inputs, authority/context/body fingerprints and original error identity/order. Any intentional per-case volatile identity normalization must be explicitly listed and justified; do not broadly drop differing fields until outputs match. No elapsed-runtime comparison is an acceptance oracle here.

Subject to these conditions, the design can exercise the missing success semantics without claiming a protected real-time launcher run. Actual implementation and count/clock/cleanup proofs still require exact code review. No source, fixture, database or Mock call was executed by this reviewer.
