P1 — Event.wait binding: SemanticClock installs the already bound `self.event_wait` on the Event class. It remains bound to the clock and is not converted into an Event-bound ordinary function. Thread.start's internal Event.wait() can consequently raise missing-event TypeError, while wait(timeout) can pass timeout as event. Install an ordinary function descriptor accepting event and forwarding to the clock. Account explicitly for that forwarding frame when matching the original caller code. The [CPython 3.12 method implementation](https://github.com/python/cpython/blob/3.12/Objects/classobject.c#L299-L320) distinguishes bound method objects from function binding. A pure Event/Thread unit can establish this before any prefix/Mock execution.

P2 — false-positive negative oracles: the observer catches every BaseException and wraps it as TailStop(error), while mutation/revocation/write-fault cases accept merely a non-None original error. An unexpected harness AssertionError, KeyError or failure before injection can pass such a negative case. Require exact injection witnesses and stage/commit assertions; mutation/revocation must observe the intended original DomainError/code/gate. The write case must prove the first INSERT succeeded and the second raised the intended SQLite CHECK IntegrityError, then verify same-transaction rollback to zero. Unexpected scheduler/observer/assertion failures remain UNKNOWN/test failures, not successful safety rejection.

P2 — template teardown: calling close() on conftest.env.__wrapped__ at its yield injects GeneratorExit. That fixture has ordinary cleanup after yield, not a finally, so close skips its engine.dispose. Manually closing clients does not prove the template Store pool is disposed. Resume to normal StopIteration, or explicitly perform equivalent cold Store cleanup in all paths, after proving heartbeat threads exited. Then check no required sidecars before physical copy. [Python 3.12 generator.close semantics](https://docs.python.org/3.12/reference/expressions.html#generator.close) support this distinction. A pure generator teardown unit is sufficient to prevent this misuse without consuming Mock budget.

Scheduling evidence gap: Thread.start completion is not initial heartbeat wait registration. The foreground can advance while waiters is still empty; add a registered/parked startup handshake for original business heartbeat threads without intercepting Thread's own internal start Event. Also a return to the next heartbeat wait proves only that its previous body ended, not universally that it committed a renewal: text_workflows.beat has a contention-deferred re-park branch, and dead threads disappear from the due predicate. Observe original Store.heartbeat returns/failures/sequence or accurately label park as body completion and retain original failure-state handling. Do not manufacture a committed-renewal ACK from park/death alone.

Timeout precision: the 300-second healthy() check currently runs only at Event.wait boundaries. It is a cooperative scheduling timeout, not an interrupting total watchdog for fixed-clock foreground G0 work; a background assertion can terminate only the daemon thread. Check real deadlines at case/G0 entry and exit and retain an existing outer test process timeout. Do not describe this field as a hard total execution bound. No new launcher/component is requested.
