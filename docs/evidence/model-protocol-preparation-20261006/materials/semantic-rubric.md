# 人工语义验收量表草案（不得发送给 provider）

这是开发代理拟定、独立于待实现生成器输出的人工核对用 oracle 草案。owner 尚未签收，独立审核只能确认草案自洽与边界；不能写成真实人工业务验收或模型已通过。当前所有模型语义结果 NOT_RUN。不得把本文件、gold JSON、隐藏预期、量表打分或冷包答案加入模型上下文。

先做独立的字面检查：资源 ID/修订/hash、行号、quote 精确匹配；然后做下列语义核对。字面引用正确不代表语义正确，Schema 通过也不代表业务正确。表达可合理改写，条件、否定、单位、先后顺序、例外、证据和判定必须保持。

每个适用维度按 0/1/2 记录：0=缺失或错误；1=部分正确但不能完整支持结论；2=完整正确且有证据。没有模型结果时记 NOT_RUN，不打0或编造总分。总分仅描述，不替代关键断言；此四包的候选 PASS 需全部适用维度为2且没有硬失败，最终仍须 owner 确认。

A案例判定的精确语义是“现在不满足提交前提”：源缺主管批准；冷缺参加证明，已有组长批准但不足以解除证明禁令。不得仅从“结束2天/10自然日”或“结束1工作日/5工作日”推算精确日历截止日期：没有日期、工作日历和计日规则，绝对日期应UNKNOWN。也不能把案例称为两条规则自相矛盾。

B的合法保守行为：T2保持允许性UNKNOWN、输出相互冲突的两侧证据、停止导出、要求有权责任方澄清。仅拒答却不识别明确支持项/例外项，不能通过；明确违反禁令或批准前提缺失的T1也不能伪装成规则优先级问题。SUPPORTED仅表示文本支持性，仍无执行授权。

验收记录须保存所有案例的原始输出、语义每维结果、字面检查结果、失败与修复；源与冷分别记录，不能只报告成功项。最终独立人工判断不得由同一生成器自由更改 gold 或降低要求。owner改变标准后要修订并重评，不覆盖本次冻结版本。此小样本不支持准确率/通用性/业务价值推断。
