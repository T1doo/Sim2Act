本文件由准备代理据新材料编写，供未来材料owner和独立评审者确认。它没有独立人工确认资格，不是实际执行答案，不得送给目标模型、作为产品parser或从中合成被测系统输出。当前实现者无需阅读；若已阅读必须记录暴露。以下是应核对的语义点，允许符合材料的不同拆分/命名，不要求固定条数、item_id或逐字摘要。

## 材料A

1. 第1行是有条件的风扇运行要求：室内有人且外门关上，两个条件为合取，不可变成任一条件。原文没有说无人/外门开时一定停止风扇，也不能从该必要适用范围推断所有其他情形。
2. 第2行清洁周期暂时覆盖第1行运行指令：清洁结束之前风扇保持关闭。例外对象是运行要求，结束边界为清洁结束，不应把它连到提醒或声响选择。
3. 第3行烟雾指示亮时风扇保持关闭，即使室内有人。其例外/禁止仍作用于风扇运行，而非禁止提醒；不可改写成烟雾触发启动。可把它表达为独立有条件要求并明确与第1行的覆盖关系。
4. 第4行包含空房已持续四分钟之后显示通风提醒的要求，以及确认提醒只清除提醒的要求。时间不是四分钟内/立即。不得把确认解释为启动/停止风扇、重置清洁周期或清除烟雾指示。原文不说明确认后是否再次提醒，不补成确定行为。
5. 第5行明确提醒是否发声尚未决定，必须保留未决；不能默认为静音或鸣响。该未知针对提醒声响，不使全部风扇规则失效。
6. 条件/例外可单独成项，也可由清晰摘要与targets表达；引用应包含相关条件、until、even when和only所需范围。不能因为quote匹配就认可其作用对象。

## 材料B

1. 第1行规定标ready之前，guard和checklist都需要有记录的inspection。是两者合取的必要前置，不等于有记录就必定ready，不等于检查一定通过，也不要求材料未提到的审批人。
2. 第2行damaged guard使station unavailable，即使checklist passed。不可改成仅当checklist未通过才不可用。该条可作为带条件的要求并标明对ready可能性的例外，不能把guard损坏改成checklist损坏。
3. 第3行reserved station用reserved代替ready标签，且使用前检查要求仍有效。预订不是免检许可。把它作为ready标签规则的条件性替代应能看出关系；不得从其推出预订时可以带损坏guard使用。
4. 第4行缺inspection record显示review-needed，不能假定pass。不要把缺记录等同明确failed inspection，也不要漏掉“never an assumed pass”的禁止推断。
5. 第5行明确三项未决：谁可以清除review-needed、reservation持续多久、reserved且damaged guard时显示哪个标签。前两项不能猜管理者/固定时长；第三项不能擅自定reserved/unavailable/review-needed优先级。该项优先级未知不抹掉第2行损坏guard不可用的语义。
6. 区分label与可使用性、记录与通过、必要与充分。若实际输出声称已知道全部标签优先级或已授予清除权限，应作为实质语义缺陷，而非因结构正确而通过。
