## Shared platform and evidence

Use actual HTTP index/CSS/all production scripts on every boot and the existing shared durable_browser adapter. Actual visible page gestures create the reviewed extraction body and original strict17 scalar metadata ticket under the existing Web Lock. Independently hash the complete actual review, candidate, source proof and full ExtractInput body; never accept key-only self-echo.

The preaccept case intercepts the original fetch before sending any RPC/HTTP to the API. It saves the exact original wire and immediately reports a controlled delivery error to that page. The product callback therefore releases its Web Lock normally, and the whole old JSDOM closes. It never force-releases a lock. Later a test-fixture action dispatches that saved wire exactly once to actual HTTP. This is controlled transport delivery, not a claim of native-browser or genuine network concurrency. The backend suite owns actual two-transaction race qualification.

Keep `requests`/wire hashes, actual response bodies, asset boot/path/status/SHA256, visible gestures, storage raw, close DTO, terminal receipt hashes and lock events. Label fixture delivery explicitly; it is neither a page retry nor a newly constructed extraction body.

## Case: preaccept-close

1. A opens source through actual directory/instance/result extraction, explicitly previews and confirms one exact original body. Capture before-API transport attempt, reject delivery to A, prove original ticket persisted, release the normal Web Lock, and close all of A's JSDOM.
2. B cold boots with shared persistence, opens the same authorized source, and sees the readonly original key. Cold opening produces no POST/new UUID/by-key read. User explicitly GETs the original key; actual HTTP400 OUTCOME_UNKNOWN keeps the ticket and edits/commit locked.
3. User explicitly invokes `pb-spec-close-intent` using CloseInput `{identity: original17, consent: CLOSE_ONLY_THIS_UNACCEPTED_PB_EXTRACTION_KEY}`. The frozen close gesture sends only POST200, validates the metadata receipt and keeps the original raw/inputs locked. A separate click on the existing recover control must GET the original terminal receipt before any raw may be forgotten.
4. Backend checkpoint proves CLOSED_NOT_ACCEPTED/NOT_ACCEPTED and zero app/runtime/Grant/Run effects. Controlled fixture now dispatches the exact saved original wire once. Actual409 must preserve zero business effects.
5. No automatic new key, preview or POST occurs. User explicitly edits/previews a new key, separately confirms and commits once. Exactly one new app from that new key is accepted; no implicit Release/instance/Run/model call occurs.

## Case: accepted-refuse

1. A performs original explicit review/confirm. Actual API accepts201, then the controlled transport drops that receipt. Close all old JSDOM after its normal callback releases the lock; retain exact ticket.
2. B cold opens original source and explicitly invokes CloseInput for the original key. Actual409 rejects closure, ticket remains exact, and no new key/POST is created.
3. Reopen the source if the refusal invalidates protected content. Explicit original-key GET plus fresh app GET must recover the accepted original app and clear only the verified original ticket. No cancellation or replacement app is created.
