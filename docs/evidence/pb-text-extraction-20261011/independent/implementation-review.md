# Read-only P-B implementation review

The reviewed slice is limited to initial `goal_application` generated registered literal text applications and an actual completed durable AppRun. The selected pure literal AppRun must have zero model Attempts and one exact typed record and one verified result operation. Upstream generation Attempts and wire archives are independently revalidated by the existing text origin path; zero Attempts for the selected pure transform is not a claim of real model verification.

Extraction clones the existing literal logic and schemas into a new `task_run` application using a different already authorized TXT/MD binding and its existing runtime. The full original GoalCard remains provenance and retains its original material references. The new manifest binds the new material. There are no new grants, principals, operators, model calls or database tables. The original source remains part of the current audit authorization and hash checks; this implementation does not retire the original source or prove absence of all original-source reads during a Worker cycle.

The existing `task_extractions` row is an independent anchor. Loading a task application recomputes the exact derivation from its accepted source, target and request. The text task candidate also contains the full `extraction_request`, including original key. This prevents switching a candidate's key and re-signing its ordinary candidate fingerprint while preserving the independent accepted derivation.

Three controlled keyed HTTP responses demonstrated the first real defect: a wrong third application ID, a replacement candidate fingerprint and a coordinated ID/fingerprint of a genuine other-key task application could install an incorrect application. Candidate 2's receipt checks plus `showApp` installation callback reject all three. Failed installation retains the original pending key. If the source panel is hidden by clearing the preview, a visible source-list reopen restores the same request for GET-only recovery. The independent probe ends after the correct installation; the separate maintained page suite covers cold Worker reuse.

The second real defect was a foreign-owner extraction API doing a private full Run SELECT before ultimately returning 403. The proof records SQL only and does not claim foreign row contents were exported in an HTTP response. Candidate 3 places a principal-filtered project metadata query and project ownership check before the full Run query in the same transaction. The full query includes exact Run, principal and project. It adds no Grant requirement to metadata stop controls. The final independent SQL probes and the maintained SQLite protected-cell barrier test verify the relevant boundary separately.

UI qualification uses monotonic workspace, app, goal, identity connection, extraction edit, instance and Run generations. Each awaited request or digest and the installation callback recheck the frozen context. Runtime term and new material remain distinct from the original provenance. Input-event edit/undo tests are synthetic JSDOM events and are not native OS or browser undo validation.

New application and release/instance owner state remains PENDING and does not inherit any source owner statement. The current owner review entry is unsupported for the new task family. Technical result verification stays separate from human acceptance: semantic UNKNOWN, human semantic NOT_RUN, LIVE0, formal publication false.

This file records code review, not an additional passing test node. Final execution counts, exact source hashes, raw failures and limitations belong to the final review and archive manifest.
