# 本次生成授权入口与恢复

本地工作树阶段证据，尚未构建进新的 Windows 包。基础提交 fe28440d；具体改动以工作树及测试输入清单为准。

- 新版范围 `pa-intern-generation-approval.v3` 明确使用逐 Run 批准选择；安装设置必须显式启用，旧范围继续要求原启动选择。
- 首次初始化时，用户填写模型 Key 才启用生成入口及逐 Run 选择。每个范围仍需单独准备、审阅、勾选、批准和提交；初始化不批准任务。
- 现有目标卡页面加入准备、明确同意、授权和回执恢复。保持既有样式体系。
- 准备和批准都是冻结的单次请求；POST 结果未知后仅按原键 GET 恢复。恢复不会新增批准、模型调用或延长期限。
- 原准备键和批准键可复制；关闭页面后可手动填回，通过只读 GET 恢复。不会保存 Key 或令牌到浏览器存储。

- `consent-recovery.xml`：33 项 API/Worker 受控测试通过，包括原范围兼容、4096 输出协议和恢复键校验；合成模型，无真实联网请求。
- `consent-navigation.json`：现有前端脚本的 30 项合成 API 导航检查通过。首次运行发现初始化顺序问题，修复后通过。
- `tests/frontend_generation_consent.cjs`：8 类控制器场景通过，包括未勾选不发送、未知批准不重发、原键 GET 恢复、过期页面上下文拒绝、清空页面状态后的原键恢复及原期限保留；隔离控制器、合成 API。
- JavaScript 语法检查通过。

尚未验证：新入口的实际 Windows 渲染、真实模型、同版本发布包、关闭重开、完整自然 P-A/P-B 和 R0。遵照用户当前限制，本阶段未操作原生窗口。不能将以上测试当作产品全流程验收。
