# 字段来源约束协议 v6

针对85b8b619实际模型修复后错误使用 data.hash 的失败，新增 `compact-candidate-json4096.v6`。候选 Schema 明确每个输出必须引用动作步骤、字段名等于输出键；输入 term 来自用户输入，resource_id 来自材料绑定。步骤和绑定 ID 仍由模型声明，完整目标和材料事实原样保留；没有人工生成候选、执行结果或代填输出。

v1—v5 仍使用各自原消息内容。旧合同读取和确认路径保留。新协议沿用4096候选输出、最多3请求和64000总保守预算，不改变严格 preflight。

新增测试使用独立 JSON Schema 校验器检验正确映射和实际失败的错误映射。jsonschema 仅列在可选 test 依赖中，不加入产品运行依赖。

第一轮收集测试因本地测试环境没有jsonschema而失败；安装到独立测试目录后10项通过。另25项原提供方测试通过。压缩重复 Schema 后重新运行10项相关测试，结果见最终XML。紧凑 Schema 与原请求字节兼容脚本通过。

固定测试输入的示例消息尺寸：v5 10949字节，最初v6 13038字节，压缩后v6 12143字节。这只是示例提示长度，不保证实际三次调用一定都能装入剩余预算；原预留机制继续逐次判断。

此工作树版本尚未构建或运行真实模型，不宣称上次失败已解决，也不代表P-A/P-B或R0通过。
