# Tail and Run-predicate diagnostics: design-only review

Result: CONDITIONALLY_IMPLEMENTABLE_DIAGNOSTIC_DESIGN_PENDING_CODE_REVIEW. No execution/grant/window ACK. No product file changes or business optimization are proposed by this design review.

The proposed launcher-only observation has a relevant narrow target: the last actual window reached the second original commit and failed in `_require_run_context_row` before its later end/stop diagnostic. Reading the already-passed arguments after that failure can supply a bounded diagnostic without a new SQL read, original guard replay, wall-clock sampling, authority or model call. Four fixed tail regions can locate remaining local costs without changing the original production functions.

Required Run-predicate wrapper semantics:

- Call the original exactly once with untouched positional/keyword arguments, original at and `_guard`. It must retain original short-circuit ordering and every original guard call. Catch only to record evidence and bare-raise the same original exception object; a diagnostic failure cannot replace it or turn refusal into success.
- Only the already-bound exact target/current G0 foreground thread and its known trial/second-recheck scope are eligible. Unbound Generate/Source calls and other Run predicates remain pass-through. No broad role-name/prefix match, account helper replacement or new qualification is involved.
- Recomputed booleans are explicitly **post-failure argument readback**, not a trace of which original and-conjuncts were evaluated at the failure instant. `_trial_result(math.isfinite(...), _guard)` can itself raise before the ultimate require; a guard error is not evidence that the boolean Run conjunction was false. Record original error type/message and this evaluation basis. Mutable argument changes during original guards or cleanup cannot be retroactively ruled out.
- Derive only named booleans for identity/resource/version/status/finite relations and the four scalar deadline values actually available to this predicate: lease_until, created_at + contract.caps.run_seconds, contract.expires_at, and their minimum. Also retain the original passed at where allowed. Do not fabricate Source or role deadlines that are absent from these arguments, or add run_seconds twice. No new time.time call, SQL, `_guard`, model_dump, repr, serializer or callback.
- Exact safe storage/types must be verified before post-failure comparisons or arithmetic. Malformed/nonfinite/foreign values cause incomplete evidence, not arbitrary additional user equality/property/iterator callbacks. Incomplete or unavailable booleans are not false and cannot identify a unique failed original conjunct. No identity/resource strings or content are emitted.

Required timing/proxy semantics:

- Fixed bounded rows only for second_prefix, recheck, second_commit, scope_exit; monotonic/thread-CPU clocks are independent diagnostic clocks, never substituted for original business times. Clock/counter/report failures mark incomplete while preserving original return, exception and cleanup control. The scope proxy must delegate original __enter__ and __exit__ exactly once, preserve the original yielded value and exact suppression result, and retain the original body or exit exception as applicable.
- scope_exit starts at original context exit, not body entry. second_commit includes its observed recheck; subtract only successfully observed, correctly nested recheck spans for a clearly named residual. Missing/invalid/inconsistent clocks or counter deltas invalidate the residual. This is not all-child exclusive time. Nested counter work must not be double-counted in totals advertised as disjoint.
- Aggregate existing checks/input_key/codec counts without an extra graph traversal, bytes re-encoding or SHA computation. Old zero input_key counters in native stages are not zero encodings. No permission state, skip flag, cached witness or caller-visible control is created by these counters.
- Installation and final report paths remain outside the timed business work where practical. There is still nonzero wrapper/clock/bookkeeping overhead; a future instrumented result cannot be compared as unchanged-observer or normalized performance evidence against historical windows.

Minimum synthetic proof before final code review: original predicate called once and same original at/guard preserved; short-circuit/guard-raised failures retain original exception object; malformed diagnostic storage and ordinary/nonordinary diagnostic bookkeeping faults cannot create a successful business result; no SQL/time.time/guard replay; original success value unchanged; explicit scope enter/body/exit errors and suppression behavior preserved; fixed target isolation; nested tail counters and incomplete/negative-clock residual fail closed. Such local tests do not execute or authorize the fresh Mock/G0 prefix.
