## Why it remains disabled

Independent review found that temporarily disabling GC would change the original streaming bridge's observable finalizer/weakref timing. An empty `gc.callbacks` list does **not** prove those callbacks absent. The final implementation therefore never enables/disables GC. It qualifies only if GC was already disabled by the caller, with the original-frame probe also refusing normal GC-enabled operation. It also refuses nonempty GC callbacks and unknown GC module keys without dispatching foreign equality.

**Normal product GC is enabled; eligible coverage there is zero.** This is a decisive applicability limit, not a request for more model permission. No runtime hook was added, no GC policy was changed to enable it, and no new large Cold acceptance was run against an inapplicable candidate. There is no measured G0, writer or end-to-end improvement for this new implementation.

An early native import crashed because direct `tp_dict` was used for CPython 3.12 static types; it was fixed using public `PyType_GetDict`, and the failing import log is retained. An early differential command missed `tests/conftest`'s `env` fixture (32 setup errors); the final command explicitly loaded that existing fixture plugin and removed only external-PG test selectors in the child process to force isolated SQLite. No test assertion was removed or weakened.

Review also rejected the first Python-separated actual/raw bridge because its intermediate signal boundaries could change the model before serializer entry. The final C segment closes that window. The GC concern above was resolved by **refusal**, not by claiming that suppressed callbacks are equivalent. Independent review found no new concrete blocker to preserving this limited-domain implementation disabled; it did not approve production routing or a long-lock improvement.
