# 从普通成功CSV任务保存仅求和应用

适用于通过执行前明确确认、三步工具和完整MD回读的 `ordinary-csv-report.v1`。原任务须为SUCCEEDED且独立完整合同PASS；普通PARTIAL任务即使人工声明ACCEPTED，也不能用作这条来源。本片使用现有Mock配置的确定性工具，提取和求和运行均不调用模型，内部版本仍未正式发布。

1. 在项目任务历史打开原成功CSV报告。原报告及文件保留；点击“读取求和来源与已有授权CSV”。此步骤只读取，展示精确来源证明。
2. 选择另一份已有授权CSV草案，核对材料ID/hash和沿用的runtime，填写新应用名称。目标须位于同项目、内容与原来源不同；不会自动新增身份或Grant。没有可用目标时，先通过已有材料/CSV草案入口明确准备授权。
3. 明确勾选“只提取求和步骤，不包含原完整MD报告”，再保存。本次只保存一个求和候选和原key持久回执；不预览、创建版本/实例或自动运行。输出限来源、列、记录数、精确合计及hash。原完整报告PASS只作为来源证明，不成为新应用的MD生成、保存或验收承诺。
4. 点击“打开仅求和应用并验证新输入”。在新CSV上明确选择数值列，执行独立预览；无效列或非数值输入会失败，不复用旧答案。原应用入口还会独立重验来源、目标和当前权限。
5. 沿已有控件核查内部版本，查看精确快照，另行勾选确认并保存，再创建独立实例。内部Release不可变，实例结果与定义分开。
6. 从项目历史刷新保存应用后返回“应用”，在统一目录找到“CSV单步汇总 · 普通成功任务提取，仅求和、不含MD报告”。打开已有实例，选择本次列并明确提交。后台建立新的真实Run和结果版本；历史结果不是本次结果。既有验收状态区域目前只返回PENDING / UNSUPPORTED_CAPABILITY，此CSV家族暂不能提交人工声明，本片不新增CSV人工验收合同。

原来源引用真实冻结GoalSpec及其Goal ID；普通CSV报告没有GoalCard，不补造GoalCard、内部实例或旧Run绑定。候选持有明确的求和范围，另外保存原合同、确认、结果、三步回执及完整报告hash用于追溯。每次候选读取、版本预检/提交及实例运行都会重验来源。原材料或原成果不可读、目标授权撤回或证据改变时停止，不补权。排队后撤权沿原Worker进入WAITING_RESOURCE/GRANT_REVOKED，无新结果，不能叫作成功或擅改为FAILED。

提取的原key和正文一经发送便固定。受理响应丢失时保留UNKNOWN，点击“仅GET恢复原key回执”；查询不到不证明未受理。可手工填写原key进行只读恢复。另行勾选重试仅重发原key/原正文，不生成另一个请求。页面内存保存未决正文，服务端持久保存已提交回执；未承诺浏览器关闭前尚未提交请求的持久化。同key同正文只保存一个候选，改正文冲突；新key代表另一次明确提取。

正常后台重画保留同一Run版本下的选择与确认；工作区返回会重新读取来源并清除确认。项目、账号、任务导航后的迟到回复不会安装候选。提取不新增Resource、Principal、Grant或权限动作；原报告执行及目标预先授权仍各有既有副作用，不能把整条准备过程称作零新增Grant。
