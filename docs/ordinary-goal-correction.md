# 将普通任务的人工拒绝带入一个新修正Run

适用于执行前已冻结人工标准的普通已保存Goal任务：旧v1保持只读，v2沿用已明确选择的一份MD保存合同。当前片仅Mock，真实模型额度0。此功能不覆盖内部自然应用已有的修正入口。

1. 从任务历史打开已完成的普通Run，读取当前完整证据，准备并逐项提交本人声明。至少一项明确选择“拒绝”并填写理由后，显示“根据原拒绝另行创建修正任务”。拒绝本身不提交新任务。
2. 点击“读取新修正任务的精确预览”。核对原Goal全部字段、原标准、所选材料ID/版本/hash、原拒绝条目及理由、原结果和本次限额。预览不写入Run、Resource或Grant。
3. 另行勾选确认，再点击“明确创建新修正Run”。服务端重算当前拒绝和版本、重新检查本人及原项目runtime对精确材料的权限，有MD时另检查原项目保存权限。请求正文只含精确预览/声明指纹、序号、显式同意与新请求key；理由由服务器从不可变原声明提取，不能用文本授予权限或放宽工具。
4. 回执确认后点击“打开已接受的新修正Run”。新Run有自己的ID、队列、预算、工具调用和结果，反馈仅放进原Worker的用户JSON消息，原Goal/标准不改。新结果显示原拒绝问题但不宣称已经修复，技术仍PARTIAL，自动验收NOT_RUN，语义UNKNOWN。新Run人工状态从PENDING开始，须另行读取证据并逐项声明。

每个父Run在当前有限片最多一个修正Run，不接修正的修正；不同key不能创建兄弟，失败不释放这个位置。相同key和正文返回原Run，改正文返回冲突。原请求接受结果UNKNOWN时保留原正文/key：显式GET恢复；未查到不表示一定未接受，可另行确认仅重试原key/原正文，不自动重发或生成新key。浏览器意图保存在页面内存，服务器受理合同/请求/来源链接持久化；不宣称跨浏览器重启自动恢复。

旧Goal历史、Run、人工追加账本/封印及旧文件原字节保留。MD成功时新建一个Resource及原政策的两条resource.read Grant，不是零副作用或零新增Grant。新增Grant可使父声明的动态视图变STALE，但不会改写其原REJECTED记录；已接受修正依据自身明确同意、冻结的父证据和当前必要权限继续重验，不追认父声明。撤回父拒绝、修改原Goal头/证据或撤销必要权限仍会阻止后续读取/运行，不补权。

页面在账号重连、项目/任务/工作区切换和同Run重绘后丢弃旧确认、旧控件及迟到回调。撤权立即清理旧成果及拒绝正文；返回工作区不复活缓存。成果查看/下载及新Run人工声明复用原入口。

本片是有限合成工程闭环，不能代签真人签收、业务语义改善、真实模型、完整P-A/P-B、PG、Windows、原生浏览器、独立worker进程重启或正式发布。

唯一子Run约束使用新增元数据表 `ordinary_correction_links`（parent主键、child唯一）。它由既有显式 `python -m sim2act.cli migrate` 增量建表，API/worker不自动DDL；本任务未执行PG迁移或运行角色权限配置，不改变现有凭据或角色。SQLite隔离旧表/数据保留探针单独记录，不代签PG。

原方案依据：[平台产品设计 §5.5—5.7、§8、§11](平台产品设计.md)要求每次敏感读取/效果前重新鉴权、相同key/相同请求取原结果、明确发起另一运行才产生新操作，以及生成前冻结验收条件；[分阶段开发计划 F2-T01/T05/T06](分阶段开发计划.md)对应原标准、统一动作网关和真实可回读成果。本片不把修正反馈改成另一套Goal或新的executor。
