# 普通 Goal：事前标准与同 Run 人工签收

在「项目」打开一个已有目标卡，先保存完整目标、材料、已知事项、假设、未决项、约束和明确的验收标准。至少选择一份当前获授权的材料，每条验收标准必须有实际内容。

在「普通任务：事前标准与人工签收」核对已保存版本，明确勾选并点击「冻结标准并执行普通任务」。这会创建一个新的普通只读 Run，冻结完整目标卡版本、来源 hash 和人工标准；未保存编辑不会纳入。原有普通任务启动入口保持原合同，历史 Run 不会因此获得补签资格。

Run 返回普通技术结果后，在同一成果画布找到「本次普通任务的人工逐项签收」。先读取当前完整证据，再准备一次有效期15分钟的精确结果签收。每项都需要手动接受或拒绝并填写理由，随后由本人勾选声明并提交。任何一项拒绝会得到人工 `REJECTED`；全部接受为人工 `ACCEPTED`。页面保留逐项声明、理由及追加历史，也可明确取消待签收或撤回已提交声明。

这是一份用户声明。技术状态仍是 `PARTIAL`，自动目标验收仍是 `NOT_RUN`，技术语义状态仍是 `UNKNOWN`，正式发布关闭。它不证明模型语义正确，也不会获得应用化成功资格。模型工具没有签收接口。

声明人必须同时是当前项目所有者、Run 创建者和冻结 Goal 的所有者。正文和提交都重新检查本人及原项目运行身份对每份材料的当前权限，并重新核对真实工具读取回执、精确结果版本及指纹。Goal 卡再编辑后，旧 Run 的当前签收为 `STALE`；历史声明保留，需使用新目标版本创建新 Run。取消、失败、运行中或有未知工具结果的 Run 不能签收为成功。

账号、项目、Run 和工作区切换会使旧控件与迟到回调失效，新的页面范围不会继承勾选和逐项判定。未确认的请求保留原 key 和原内容；只能明确读取原 key 回执或明确重试原请求。读取恢复不自动重新提交，也不会重新激活历史声明。

材料撤权后，正文和缓存成果清除。从持久任务历史打开该 Run 后，可明确点击「只读打开此 Run 人工声明元数据 / 停止入口」，保留仅元数据的取消或撤回能力。权限恢复后，需从历史重新读取完整 Run 才能重新核对正文。

实现使用现有 Worker、工具、双主体授权和 owner 命令协议；普通 Run 使用独立范围的追加账本表 `ordinary_owner_records` / `ordinary_owner_seals`。它们由已有迁移命令的 `Store.initialize()` 增量建表；没有修改旧实例账本、旧指纹、新增角色、Grant 或 executor。SQLite 合成测试覆盖增量建表；PostgreSQL迁移与真实应用角色验证未在本次执行。

设计依据：[产品设计 §5、§11](平台产品设计.md)、[F2-T01 与 F2-T05](分阶段开发计划.md)。本次工程证据中的点击和人工声明均由合成测试模拟，不是真实用户签收；真实模型、真实语义/场景、Windows、原生浏览器、PostgreSQL和远端CI均未执行。
