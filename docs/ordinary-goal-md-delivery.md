# 已保存普通 Goal：明确交付一份 MD

在「项目」保存完整目标卡、材料和明确的验收标准。打开目标卡后，在「普通任务：事前标准与人工签收」明确选择「要求在本项目保存1份MD成果」，再核对、勾选并启动。该选项默认不选；更换目标、账号、项目或工作区后需要重新明确选择。

这会创建一个新的普通 Run，事前冻结完整 Goal、材料版本、必须交付一份 MD、当前项目范围、最多一次保存、8000字符上界及原工具定义指纹。保存工具还有既有32768字节参数JSON上界。仅选择写入选项不执行工具；启动前须有本人及原项目运行身份的当前项目保存权限。原有只读启动和签收 v1 合同保持只读，历史 Run 不获得写入或补签资格。

原 Worker 读取材料、调用原 `artifact.save_text`，同事务保存资源、operation intent、effect及回执。正常保存沿用既有政策派生两条成果读取 Grant；没有新增身份、角色、工具或 Grant 类型。实际产生文件后，平台独立回读本 Run 的资源 ID、项目、MD 格式、原始内容及 hash。`DELIVERED` 只表示这一份文件确已保存、回读，技术状态仍为 `PARTIAL`，自动目标/语义验收仍为 `NOT_RUN` / `UNKNOWN`。

同一成果画布提供「查看此成果」「下载此成果」；每次操作先重新读取精确 Run，再检查资源当前权限与内容 hash。MD按原始文本显示，下载绑定本 Run 和资源 ID。人工逐项签收另行准备并由本人明确提交，包含原目标标准及冻结的精确文件检查项；接受声明不会成为自动语义通过或应用化成功资格。

若模型只返回答案而没有实际保存文件，交付失败且不可签收。同批请求多份文件会在派发前被拒绝；先保存一份、后请求再次保存时，第二次拒绝，原文件及回执保留，任务明确失败。失败画布仍可查看、下载已知合法文件，但它不能使失败任务获得签收资格。

同一逻辑保存调用只回读原回执；新的保存调用不能产生第二份文件。写入、最终完成、查看下载和提交声明都会重验所需的当前权限与精确文件证明。撤权会拒绝相应操作，不自动恢复旧授权。

本片只接通 MD，不扩大到 JSON/CSV 文件交付、任意执行器、业务记录写入或外部系统。后续“拒绝条目和理由带入明确的新修正 Run”是另一条候选，当前未实现。

工程验收全部使用合成资料和 Mock响应，用户选择及人工签收均为测试模拟。没有真实模型、真人签收或真实语义/业务评价，也未运行PG、原生浏览器、Windows、独立进程重启或远端CI。前片285的UNKNOWN动态证据仅覆盖实际已接受、丢失回执后原key GET恢复，不覆盖原body重试按钮或重新授权后重开完整矩阵；其“新Worker”是新建对象，不能称独立process restart。
