# Sim2Act 前端完善与 R0 收敛计划

Codex 执行版 · 2026-11-05 · 审阅、设计与验收计划，不是完成报告

核心结论：新版已经修正了几项关键的结果归属问题，也具备清楚的三工作区骨架。下一轮不应再推倒重做，而应收敛页面层级、应用使用路径、材质与全部交互状态；与此同时，单独完成同版本桌面交付、真实模型两路径及 R0 验收。

### 本计划的两个完成目标

UI-ready：用户能明确区分当前草稿、下一次运行输入与所选历史成果；三个工作区、检查面板和已有高级流程使用同一设计语言；异常、键盘、缩放、触摸与动态效果有真实验证。

R0-ready：同一冻结版本具备 P-A 目标生成、P-B 任务应用化、新输入复用、依赖修改、授权与恢复的完整记录，并在声明的 Windows 11／PostgreSQL 环境复现。UI-ready 不自动推出 R0-ready。[R1–R4]

### 必须保留的工程成果

保留静态 HTML/CSS、分模块 JavaScript 和 Python API；保留原控件身份、事件处理、权限、版本、审批、请求键和恢复流程。没有理由为了玻璃效果迁移 React/Tailwind，也不能把请求回执未知改成可重复提交。

配置式桌面 supervisor、C# 启动分支和 PG 驱动打包入口已经有源码与文档。不要按旧发布报告重新实现这些组件；当前重点是核对构建产物、真实环境和组合验收。[R5–R8]

## 03 前端问题清单 A：成果与检查

P0/P1 · 每条均包含证据、影响、实现职责与关闭条件

### UI-01｜P1｜成果前置状态区过高

证据：项目三种宽度均使用相同的多行状态堆叠；单项指标内层卡又重复框住标题、数值和记录数。影响：首要成果退到卡片中段，阅读路径被低频信息切断。改法：首行“金额汇总／已保存结果 v1 + 计算完成”，次行显示来源与选中运行摘要，紧接指标；验收缺项保留在指标旁或下一行。不要删除未提供状态。职责：结果头部、状态摘要、.result-document、renderInternalTaskResult。关闭条件：1440×900、1366×768、1280×720均先看见对象名称、数值和重要未确认状态；布局高度以截图验收，不用缩小字体达标。

### UI-02｜P1｜检查入口看似页签，但实际打开旁栏

证据：主成果顶部“来源／验证／版本”与旁栏内的四页签同时出现；主区入口没有正在显示的内容区。影响：切换页面与打开检查两类行为混淆。改法：主区使用“来源详情／查看验证／版本记录”轻按钮，旁栏才采用真正的页签；或把主区改成确实切换内容的页签，两者择一，推荐前者。职责：检查触发器、aria-expanded/controls、openFrontendInspector；旁栏页签按 APG 键盘模式。关闭条件：键盘与鼠标行为一致，Escape返回原入口，无自动写请求。[W7]

### UI-03｜P1｜检查栏长ID压过业务名称

证据：project-inspection.png 的“当前任务检查”后完整 Run ID 换成多行，旁栏大半为空；左侧成果保留是已解决事项。影响：看不到正在核查什么业务对象，技术身份占据标题。改法：标题“金额汇总 · 检查”，小行“结果 v1 · 运行 …7d9ea”，完整ID以详情/复制保留；增加各状态的简短含义与原有处理入口，不能补造验收。职责：检查标题、字段列表、身份详情。关闭条件：切换成果后名称、版本、来源和检查同属一个Run；复制使用完整原ID。

### UI-04｜P0候选｜“结果回读一致”的证明范围需专项审查

证据：apps.png 明确区分金额输入和人数历史结果；新测试声称拒绝未知结构升级为PASS，但上传包无新版实现。影响：若只验证列名/数值相等便显示核查通过，可能仍扩大证明范围。改法：核对新版 use.js 的真实绑定条件，至少覆盖实例、Run、Release、结果版本与合同；无法证明时显示“已保存，核对记录未提供”。职责：结果投影与原只读核对，不新造权威状态。关闭条件：用金额30/v1与人数5/v2交叉污染、旧响应、缺字段、版本冲突反例验证；缺陷是否存在以代码与测试为准。

## 04 前端问题清单 B：应用、资源与小屏

P1/P2 · 不用删功能来制造简洁

### UI-05｜P1｜应用目录仍先展示管理，再展示使用

证据：apps.png 同名条目已归组，但组内先出现材料授权、最长24小时说明和管理按钮，然后才是“使用此本地实例”；主区首屏仍展示冻结声明与只读验收。影响：高频运行与低频管理竞争。改法：组头为应用名称与实际版本状态，首要入口“打开”；进入后分为“使用／历史／管理”，默认使用。授权、版本、适用范围和验收仍可达；影响本次提交的确认必须在提交前可见，不自动合并或勾选。职责：use.js目录、实例选择、运行面、原声明与验收节点。

### UI-06｜P1｜工程措辞仍主导日常页面

证据：“从Goal创建自然应用”“为下一次新Run事前冻结本人适用范围声明”“技术执行：执行完成”等仍可见。影响：用户需要先理解内部实现，且重复状态降低阅读密度。改法：主文案改为“从目标创建应用”“为下一次运行声明验收范围”“执行完成”；精确合同、错误码、原始状态和完整字段在详情保留。状态词典区分：未提供记录、未执行、待确认、不适用、失败、未知。职责：集中展示文案映射；未知枚举保留原值，不归为成功。

### UI-07｜P1｜资源表单与列表信息密度仍不协调

证据：resources.png 搜索框近乎铺满工具栏；三行都常驻“指纹”折叠入口，格式同时在图标、扩展名及第二行出现。影响：列表像技术记录，而非可选择的工作材料。改法：搜索约320–440px自适应，数量与视图切换靠右；每行用名称+一个格式标记，指纹放“详情”；授权范围只能由现有数据支持，不能因项目可读便标成应用可用。职责：资源工具栏、行布局、详情和授权定位。

### UI-08｜P1｜手机已能看到主按钮，但四层导航仍占前231px

证据：375/320图依次包含项目栏、一级导航、分区与历史、指令/成果；键盘快捷键仍占手机辅助行。影响：小屏工作区域被持续消耗。改法：保留一级导航和“配置／成果”；项目分区可以紧凑二级入口处理，隐藏不适用的快捷键提示；不能删历史或错误。关闭条件：真实触屏和软键盘下主操作、焦点与错误可达；补375×667、320×568，允许正常纵向滚动，不强求一屏放完。

### UI-09｜P1｜玻璃有了，但内层大卡与描边仍过多

证据：项目外层乳白卡+大面积内层白卡，深色两层接近同色；应用按钮仍多为细描边小方块。改法：主卡承担乳白材质，指标区用排版而非再次整圈围框；输入保留清晰边界，浮层承担更明显磨砂。按钮按主／次／工具／危险分级。职责：语义token与表面组件，详见下一页。

### UI-10｜P2待验证｜动态与运行可用性不能由稳定图判断

证据：截图拍摄关闭动画；资源页出现worker OFFLINE，项目页为“正在检查后台”。不能判断是暂态、只读环境还是故障。改法：测试真实加载、超时、未知请求与停止；动态只反馈实际状态。执行器不可用时按后端规则说明可排队或不可执行，不能前端猜测。

## 05 视觉系统：浅蓝乳白工作面 + 局部磨砂

以新版本为底稿，不恢复旧重磨砂方案，也不把所有表面透明化

参考取舍：Linear的界面重整强调外壳、标题和面板之间的对齐与信息密度；Fluent区分实体面和用于临时浮层的Acrylic；Geist将按钮尺寸、加载、禁用与图标语义统一。这里只借用职责和状态原则，不复制品牌配色、React接口或付费组件。[W1–W4]

| 职责 | 建议起点（须实测） | 限制 |
| --- | --- | --- |
| 背景氛围 | 保留浅蓝；柔青与淡紫各一层；装饰只在外缘/空白可见。 | 不新增网格、全屏追光、持续扫光或WebGL背景。 |
| 永久工作面 | 配置/成果使用乳白底，不透明度约90%–96%；轻亮边+低幅阴影。 | 正文、表格、确认和错误区域近乎不透明；不靠透明度牺牲阅读。 |
| 外壳与浮层 | 顶栏适度半透明；菜单/选择器底约82%–90%，blur 12–20px。 | Web CSS是视觉近似，不宣称原生Windows Mica；低性能/不支持滤镜时不透明降级。 |
| 主按钮 | 保留蓝色；上下微明暗变化、顶部细高光；高40–44px。 | 主操作仍是当前表单唯一强强调；禁用不发光、不响应按压。 |
| 次级/工具 | 次按钮浅乳白，工具按钮无大底；圆角8/12/16px分别用于控件/次容器/主面。 | 不要每个按钮独立设阴影；危险动作不用品牌蓝伪装。 |
| 文字/数字 | 22px区域、18px功能、15–16px正文、13px辅助、32–36px指标；中文正文行高1.65。 | 不为矮窗口缩正文；不为观感增加无依据单位或动画中间数值。 |

### 实现方式

将颜色、surface、stroke、elevation、radius、motion、z-index集中成语义变量。沿用并整理现有 Professional workbench system；先清理重复覆盖，再决定是否拆文件。不要直接新增 @layer 后假定它会覆盖旧未分层规则。外层不使用整体opacity，避免文本一起变淡；不对每个嵌套元素重复backdrop-filter。[W5]

深色独立设置背景、卡片、浮层明度，不用黑白反转；实际检查合成背景上的正文和控件。普通正文按4.5:1、必要控件与状态视觉线索按3:1检查；禁用组件有标准豁免，但项目仍要求可读。装饰亮边不必全部加深成粗框。[W6]

Figma使用范围：本轮查阅了Fluent官方Figma UI kit说明及Figma公开UI kit指南，未读取任何私有设计图层。下一轮可用组件变体页做设计交接；不把获得Figma文件权限当成实现前置。[W9]

### 建议的只读展示投影

ResultView（名称为建议）：owner/project/appInstance/run/selectionGeneration、结果版本、Release引用、实际输入摘要、执行状态、工具核对、目标验收、人工签收、读取新鲜度、允许的现有操作。每个字段保留“缺失/未知/不适用”，由原回执映射；前端投影不是权限依据，按钮隐藏不代替后端鉴权。

同类结果只共用格式化函数，不强迫不同family共用不相容合同。展示函数不创建请求、写数据库、改变审批或生成新恢复键。切主题/导航/检查只允许现有必要GET；POST必须来自原明确操作。

不要一开始拆完巨大app.js。先补基线和行为测试，再将纯显示token、状态文案、结果头部等小块抽出；每一块迁移后验证原节点和事件未被复制。

## 07 动效、状态与异常体验

高级感来自可预测的反馈，而不是让工作对象持续移动

| 状态/交互 | 规定行为 | 验收重点 |
| --- | --- | --- |
| Hover / Press | 120–160ms底色/边缘变化；主按钮按下最多1px；可选局部高光仅限可点击卡片。 | 不改变点击区域、不引发布局；不可点击成果不倾斜、不磁吸。 |
