# Sim2Act 制作基准与镜头映射

本文件统一产品书、正式界面图、旁白和 H3 提示词的命名、业务状态及素材对应关系。与[制作总计划](制作总计划_阶段与验收.md)共同作为制作入口。下列业务内容用于正式设计的画面编排，实测数据另从工程记录取用。

## 统一内容

| 项目 | 制作口径 |
| --- | --- |
| 产品 | Sim2Act |
| 主张 | 让构想成为可用的应用 |
| 品牌解释 | Sim 构想，2 转换，Act 可用应用 |
| 参赛方向 | 方向 3 · 开放赋能智能体 |
| 生成模型职责 | 书生理解需求、提出规划、选择工具及根据反馈修订 |
| 主场景应用 | 科研申报助手 |
| 场景团队 | 星桥研究团队，作为故事中的设定 |
| 核心页面 | 材料清单、预算核对、问题跟进、提交准备 |
| 一级导航 | 项目、应用、资源 |
| 技术主线 | 目标规格 → 工具动作 → 专用界面 → 检查发布 → 执行复用 → 依赖演进 |
| 两条生成入口 | 从目标创建应用；从已完成任务提取应用 |
| 片尾主张 | 让每一份专业经验，都成为更多人用得上的能力 |

片中的“提交准备”对应可供用户检查和导出的材料包。画面中的动作必须准确区分查看、保存、发布应用和对外提交材料。

## 业务数据与版本连续性

| 状态 | 页面内容 | 版本关系 |
| --- | --- | --- |
| 目标与蓝图 | 新建科研申报助手，材料包括申报指南、预算表、团队资料和附件清单 | 草案 |
| 样例检查 | 附件清单发现一项缺失，指出对应条件；补齐后再次检查 | 草案检查完成 |
| 发布 | 用户确认读取材料与项目内保存范围，应用进入目录 | 应用 v1 |
| 项目甲运行 | 设备费 40,000、材料费 35,000、服务费 15,000，合计 90,000 元；预算上限 100,000 元 | 应用 v1 / 甲的结果 1 |
| 项目乙复用 | 切换到乙的材料，三项为 30,000、28,000、18,000，合计 76,000 元 | 同一应用 v1 / 乙的独立结果 |
| 规则变更预览 | 回到项目甲，将上限从 100,000 改为 80,000 元。甲的预算 90,000 元保持，显示超限 10,000 元 | 应用 v2 草案 |
| 更新范围 | 预算阈值、相关检查和提示更新；人员与已确认附件保留 | 确认后形成应用 v2 |
| 历史对照 | 旧结果继续绑定上限 100,000 元的应用 v1；新结果绑定应用 v2，并显示超限事项 | 旧运行记录保持原归属 |

把每张图中的数字填入素材内容单后再生图。不同场景的实测金额，如运营汇总的 6,240 元与 8,000 元，仅出现在相应实际案例中。

## 四项技术的可视化要求

| 技术 | 必须看见的对象变化 | 屏幕文字与解说重点 | 产品书位置 |
| --- | --- | --- | --- |
| T1 目标到应用编译 | 一个目标拆成字段、动作和检查，再对应到表单、按钮和结果区 | “预算总额”连接求和动作与预算上限检查；输入和动作有明确类型 | 第 3–7 页 |
| T2 任务轨迹应用化 | 一次已完成任务中的规则和可变材料被分组，再进入可复用应用定义 | 固定步骤、每次输入、输出与检查 | 第 8 页 |
| T3 依赖驱动演进 | 预算上限变化沿连接传播，受影响区高亮，保留区位置稳定 | 更新对象、保留对象、待确认冲突 | 第 9 页 |
| T4 执行与核验 | 同一运行连接材料、动作回执、成果和版本 | 谁提供输入、发生了什么、结果来自哪里 | 第 10、13–14 页 |

技术细节出现在机制镜头，正式业务界面使用清楚的中文标签。复杂内部标识放入详情或技术附录。原始实验图保留其记录含义。

## 画面数量与镜头映射

U 编号表示功能或页面职责，A 编号表示需要制作的视觉母版，S 编号表示视频制作单元。一个母版可以承担多个镜头，每个镜头按动作需要补开始、结束或详情状态。

| 母版 | 主要画面 | 页面职责 | 镜头 |
| --- | --- | --- | --- |
| A01 | 工作场景与构想入口 | U01、U13 | S01、S02、S04 |
| A02 | 目标规格与动作蓝图 | U02、U12、U14 | S05、S06、S07、S10 |
| A03 | 样例检查与反馈 | U03 | S09 |
| A04 | 科研申报助手首页 | U04 | S11、S13、S14 |
| A05 | 问题与条款侧栏 | U05 | S12 |
| A06 | 更换材料与独立结果 | U06、U09 | S15、S16 |
| A07 | 从任务提取应用 | U07、U15 | S17、S18 |
| A08 | 规则影响与前后对照 | U08 | S19、S20、S21 |
| A09 | 运行机制与记录布局 | U12 | S08、S24 |
| A10 | 运营与实验场景 | U11 | S25 |
| A11 | 团队能力库 | U10 | S26 |
| A12 | 品牌与人的工作场景 | U13 | S03、S27 |

E01、E02（S22、S23）引用已有真实素材时，实际画面不交由视频模型重新生成关键数据。可将原始截图作为固定图层，使用剪辑实现平移、强调和切换，外围氛围单独制作。其余正式设计页面可以通过 AI 生图完成，并接受文字和业务关系检查。

数量预算为 12 组视觉母版，最终采用帧约 24–36 张，按首尾帧需求调整。既有 17 张截图作为风格与工程素材输入，保留来源记录。两套母版探索方向只用于比较，确定后统一生成全套。

## 状态与转场的衔接

每段有一个“进入状态”和一个“离开状态”。跨段接续时沿用相同应用、字段、材料和版本。S12 的问题侧栏、S13 的发布动作、S14 的应用使用应保持导航和主要模块位置连续。S19 修改的是规则，S20 展示其影响，预算内容保持相应真实逻辑。

优先用同一个目标卡、按钮、应用图标或依赖线做匹配切。技术图和业务图互相过渡时，先保留可识别对象，再改变展示层级。正式界面正文采用稳定正面视角，科技空间与透视用于片头、揭示与片尾。

## 共享素材记录

每个素材条目记录 `asset_id`、用途、文件、来源类型、版本、对应 U/T/S 编号、关键中文、关键数字、采用状态和哈希。每段上传表把素材 ID 映射到本段的参考标签，上传顺序和角色必须明确。

主体、声音和品牌的身份描述在全片固定。分段时间从零开始，最终 270 秒剪辑时间独立管理。更新某张图时，检查所有引用它的镜头，避免不同段落混用旧版本。
