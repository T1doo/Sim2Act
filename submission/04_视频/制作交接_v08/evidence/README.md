## 生成过程能证明什么

三次generate请求之间出现材料读取回执、规格检查回执、最终候选验证事件。保存的候选包含read → model_all → verify → save步骤及字段来源。当前导出的事件没有GA_DIAGNOSTIC；不能把三次调用直接讲成三次错误修复，也不补造模型隐藏思维链。

生成运行终态为PARTIAL、草案验证为预览范围，后续保存到INTERNAL_ENGINEERING_ONLY的限定应用版本。两次实例执行SUCCEEDED，引用核验PASS，语义验收NOT_RUN、人工签收PENDING。保留原始formal_publication_enabled=false及live_allowed/dispatch_authorized等快照值，不将内部链等同正式发布资格，也不把历史记录用作新授权。

## 独立核对

运行同目录verify_evidence.py，无需模型密钥或数据库。它从脱敏原始字段重新计算请求数、用量及事件耗时，核对同实例/同应用发布关系、两次结果版本、六条原文引用与文件哈希。该检查验证随包记录一致性，不重跑产品，不证明记录来自供应商的独立签名。

完整源记录仍留项目内受控位置；包内不含密钥、配额主体、账号标识、endpoint、review token、local-installation、数据库或本机进程路径。
