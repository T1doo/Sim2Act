# 三分钟旁白粗稿 v01

> 历史稿。当前使用[四分半旁白](旁白粗稿_270秒_v01.md)，共 27 个单元、270 秒。

每单元 10 秒。文本为录音与镜头排练底稿，后续根据实际朗读校准停顿和配音时长。产品画面采用统一制作基准。

| 单元 | 旁白 | 画面任务 |
| --- | --- | --- |
| S01 | 如果一个构想，可以变成团队每天都能使用的应用，专业工作会发生怎样的改变？ | 人提出目标，目标卡成为焦点 |
| S02 | 一次科研申报，连接着指南、预算和附件。资料在变，规则在变，团队需要持续协作。 | 材料进入同一工作区 |
| S03 | Sim2Act，以书生大模型理解目标，把输入、约束和交付要求，整理成明确的应用规格。 | 目标展开成规格 |
| S04 | 同一份规格，连接用户看到的界面与系统执行的动作，让每个输入都有清楚的去向。 | 字段连接控件、动作和检查 |
| S05 | 读取指南、核对材料、计算预算、保存清单。工具按依赖协同，工作计划逐步形成。 | 动作图从左向右连通 |
| S06 | 缺少条件，系统给出反馈。用户补充后，方案继续修订，检查贯穿应用生成的过程。 | 指出缺项并补齐 |
| S07 | 材料清单、预算核对、问题跟进、提交准备。一套专用工作台，从构想中逐步长成。 | 四区界面落位 |
| S08 | 每个问题都能追到依据。打开来源，查看对应条款，让结果成为可以核对的工作成果。 | 问题打开原文侧栏 |
| S09 | 确认读写范围，保存应用版本。现在，团队可以直接打开这款应用，开始自己的工作。 | 发布与打开应用 |
| S10 | 换一份材料，启动新的运行。结果各自保存，旧记录仍然可查，能力可以反复使用。 | 项目乙运行与甲的历史 |
| S11 | 已经做成的任务，也能提取成应用。固定步骤被保留，可变资料成为下一次的输入。 | 从轨迹提取规则与变量 |
| S12 | 新输入检验复用，错误输入触发提醒。一次工作的经验，逐渐成为清楚的使用规则。 | 新资料和缺项反馈 |
| S13 | 当预算规则改变，依赖关系揭示影响，相关计算、提示和检查随之进入更新范围。 | 规则影响传播 |
| S14 | 已确认的附件和历史结果继续保留。每次修改都有范围，应用随工作需要持续演进。 | 更新与保留对照 |
| S15 | 工程记录中，书生生成的规则审阅应用，已经完成两份材料的独立运行与引用核对。 | 原始 v1/v2 结果与出处 |
| S16 | 从科研申报，到活动运营、实验复盘，统一机制承载不同的专业工作。 | 三种专用应用 |
| S17 | 当经验能够交接，当能力能够复用，国产智能技术就能更深入地服务团队与组织。 | 团队能力库与连接 |
| S18 | Sim2Act，让构想成为可用的应用，让每一份专业经验，都成为更多人用得上的能力。 | 品牌收束与定格 |
